# 动作与目标 v1 接口契约草稿

【已确认】本文仅交付设计契约；不改 `bio-brain-v2` 源码，不 commit/push。下文的职责名、信号名不声明现有实现；“现码未对齐”依据参考文档记录，不表示本次已审计源码。（本任务简报）

## 1. 范围与非目标

- 【已确认】本模块负责目标输入与现实对齐、未知时探索、多候选竞争、子目标保持与中断、动作终止，以及真实执行反馈进入经历。动作可经外置适配器调用接口；动作选择与方法学习由网络承担。（本任务简报）
- 【已确认】第一版能力范围包含多步条件反查、子目标、内部预演、现实输入到来时的中断、耐心随投入消耗；这些是交付目标，不是已有运行证据。（本任务简报）
- 【未验证/开放】上述能力的连续动力学、调度、停止条件及参数尚须核验；本稿不把范围确认转写为实现完成。
- 【已确认】第一版不包含完整长期资源安排、语言声音、成熟合成；不另设外置规划器或第二套规则知识库。（本任务简报；R1 §4.1、§4.6）
- 【已确认】`S-WANT / S-HAVE` 仅表示“想要／已有”的职责；`L-GOAL / L-BODY / L-ACTION-TRACE / L-EXPERIENCE` 在此仅约定跨模块边界，不据此批准五套独立物理网、状态侧拓扑或新的学习机制。（本任务简报）

## 3. L-GOAL / L-BODY / L-ACTION-TRACE 职责与接口契约

### 3.1 信号方向与写入边界

| 状态 | 边界／信号方向 | 责任与不得写入项 |
|---|---|---|
| 【已确认】 | 指令／驱力／探索 → `L-GOAL`（`S-WANT` 职责）→ 概念网络目标入口 | 承载“想要”的来源及目标线索；不得把目标当真实感官、真实动作或成功证据写入 `S-HAVE`／真实经历。来源优先关系见 R2 §11.5；职责名来自本任务。 |
| 【设计已锁·现码未对齐】 | `L-GOAL` → 同源底层端口 → 补全认出 → 高层反查；现实当前场 → 高层差集 | “要”和“已有”使用可对应的模式身份，但写入权限分离。目标通路不得进入真实过去或 STDP；不得直接钳高层 ID 代替认出。（R1 §4.2–§4.3） |
| 【已确认】 | 身体真实读数 → 输入接入 → `L-BODY` → 当前状态／`L-EXPERIENCE`；身体驱力 → `L-GOAL` | 身体读数可作为真实输入照常学习；“希望恢复”或“预测恢复”不得改写实际身体状态。驱力与读数须区分；本稿不定义身体编码、检测器或状态物理。（本任务简报；R2 §13.1–§13.2） |
| 【已确认】 | 网络动作选择 → 外置动作适配器 → 执行接口 | 适配器完成外部调用，选择与方法学习留在网络；不能在适配器内补一套任务规划器或教师程序。（本任务简报；R1 §4.1；R4 教师禁令） |
| 【已确认】 | 真实发出的动作 → `L-ACTION-TRACE` 专用输入 → `L-EXPERIENCE`／时间展开动作行 | 记录自身已做动作的传出副本，与观察行区分；候选、运动意图、预演不生成真实副本。副本证明动作发出，不证明外部结果发生。（R2 §11.1；R3 §3.1、§7） |
| 【已确认】 | 外部结果／身体反馈 → 输入接入 → 当前现实／`L-EXPERIENCE` → 学习 | 仅真实观测可作为结果在场与满足目标的证据；真实经历可进入过去片与 STDP。目标和预演不得冒充结果反馈。（R1 §4.2、§4.4；R2 §11.1、§11.7） |
| 【候选】 | 适配器执行回执 → 动作生命周期管理 | 区分请求、实际发出、执行结束、失败、取消确认；回执只报告接口事实。具体哪类回执产生动作副本须按适配器能力核对，不能把请求入队直接当执行。 |
| 【候选】 | 状态／输入的新现实事件 → 目标与候选失效检查 → 执行门 | 用同一已完成观测版本重算缺口与候选，执行前复核取消／满足／版本；不让不同观测批次混成一次决策。（承接 R3 §6 的推荐边界，具体时序未锁） |

### 3.2 隔离矩阵

| 状态 | 信号 | 真实过去／经历事实 | STDP | 满足目标的证据 |
|---|---|---|---|---|
| 【已确认】 | 真实外感受、身体读数 | 可进入真实观察路径 | 可按既有机制学习 | 对应结果真实在场时可用 |
| 【已确认】 | 实际动作传出副本 | 可进入专用动作路径 | 可按既有机制学习 | 不单凭动作发出判定结果成功 |
| 【已确认】 | 根目标、派生子目标、未执行候选 | 不可冒充事实 | 不作为学习样本 | 不可 |
| 【已确认】 | 预演动作与想象结果 | 不可；只入预测／想象通道 | 不触发学习 | 不可 |

【候选】跨模块最小审阅信息为：模式引用、来源、真实时间／观测版本；目标另带目标句柄与父目标关联，动作另带执行关联和阶段，候选另带所依据的缺口与差集证据。句柄只用于路由、取消和追溯，不作为规则知识；字段名、类型、存放位置未锁，不据此新增持久关系表。（R1 §4.6；R3 §3.1、§6）

【设计已锁·现码未对齐】R1 §4.5 记录的现码仍以 `W/wMax ≥ .3` 入池、汇总后 `.75` 出手；新版先锁差集计量再整体对齐，不允许把旧 W 门与新差集驱动混用后宣称完成。

【未验证/开放】binary 缺口与连续缺件强度／情景加权不能混为一种量：后者不反写前者，也不把预演成功变为现实 presence。pending 如何调制有效驱动、差集强度如何归一化、.3/.75 在新计量下是否适用，需独立核验。（R4 “D”；R1 §4.4–§4.5）

【候选】现实到来时先暂停旧预演推进，刷新现实缺口与候选；未发动作重新过门，已发动作请求适配器停止并等待真实反馈。适配器若无法停止，记录仍在执行，不能把“取消目标”记作“动作已停”；实际已发动作及晚到反馈仍保留为经历。

## 5. 案例：红场开灯／蓝场开门

【已确认】权威用例是“红灯情景＋同一按钮→开灯；蓝灯情景＋同一按钮→开门”，不是两个不同电机动作。用例≠定义；颜色是解释标签，不能成为手写条件规则。（R1 §0、§4.3；R3 §7）

| 状态 | 纸面步骤 | 预期边界 |
|---|---|---|
| 【候选】 | 假设自然经历已形成相关整团；当前红场，灯未亮，注入“要灯亮”。 | 目标只点亮“要”通路；真实灯 presence 仍缺失。此为待核验前置条件，不是训练成功声明。 |
| 【候选】 | 同网补全后减去现实已有，读出按按钮的动作叶；若另有路径则保留竞争。 | 红场只作情景证据；既不请求“执行红色”，也不把目标改成开门。 |
| 【候选】 | 候选在内部预演按下后灯亮。 | 不调用按钮接口；真实过去、动作副本、学习状态及现实满足标志均不因预演改变。 |
| 【候选】 | 实际过门发出一次按钮动作；灯尚未真实亮起。 | 传出副本入经历，pending 可抑制重复驱动；请求回执不清目标。真实灯 onset 到达后才满足。 |
| 【候选】 | 在实际发出前，现实从红场变蓝场。 | 中断旧预演并重评；若仍按下导致开门，记录真实开门，不能算开灯成功。新情景不会自行改写根目标。 |
| 【未验证/开放】 | 红场下想开门，而已学网络可能包含“移动→到达蓝场→按按钮→开门”。 | 只有补全／差集确实提供可达条件链，才能派生中间节点并落到移动、按键等动作叶；不得从缓存里的“蓝”直接制造“变蓝”任务。链竞争、父子保持与取消待核验。 |

【未验证/开放】同一按钮服务两个结果不能证明“同目标多动作竞争”已经成立；另需同一结果存在不同已学动作／路径的用例。R3 §5.1 的按结果归集 `m_B` 不能独自区分同结果多链，其公式、Jaccard、软底值均仍是候选。

## 7. 下一步可核验项

【候选】以下是后续验收提案，不是本次已运行的测试或已锁实现；先纸面对齐接口，再在获得实现任务后采集运行证据，不以固定案例脚本代替网络选择。

| 状态 | 核验项 | 所需证据／失败判据 |
|---|---|---|
| 【候选】 | 目标与现实不混写 | 同源目标注入后可认出，但现实 presence、真实过去和学习状态不变；单凭目标清空缺口即失败。 |
| 【候选】 | 同网反查与新门 | 追溯底层认出→高层补全→现实差集→动作叶→驱动→电机读数；出现 ID 查表规划、W 入池或额外乘 W 即未对齐。 |
| 【候选】 | 多步与取消 | 用自然经历形成至少两步条件链，逐步观测满足；取消根后其专属未执行子链失效。另测共享子目标、环路与深度边界；先确定归属规则再判通过。 |
| 【候选】 | 多候选与情景变化 | 检查多团同时保留、同一结果不同动作竞争、场景变化后更新候选；只演示同按钮两结果不足以通过。 |
| 【候选】 | 预演不学习 | 无真实新输入的预演前后比较学习状态与真实过去，核对执行调用和动作副本均为零；存在任何预演写入即失败。 |
| 【候选】 | 中断与动作终止 | 分别在预演中、排队未发、执行中注入真实变化／取消，记录失效、停止请求、停止反馈和晚到真实结果；不把取消命令当停止完成。 |
| 【候选】 | 真实反馈闭环 | 请求成功但结果缺失时目标不满足；真实结果到达才对齐。动作副本与结果观察保留各自时间、来源；pending 不永久压住失败后的重试。 |
