- 以仿真动态网络为基础，尽量避免固定表、硬指定连接等模板化设计，保留通用性和灵活性。确有必要的例外，要详细记录设计对象、方案、必要性和影响。

- 本轮讨论能力、行为与协作关系。完整功能图景随后整理成若干组数学或仿真题目，交给 Astra Pro 针对性解答，再检查并整合各组答案。

- Codex 补齐约束、边界与验收场景，并区分用户决定、已有约束、补充假设和待确认取舍。

- 参考旧视频与 bio-brain-v2 的设计思想：从经验形成知识，利用同一套学到的知识进行识别、补全、预测和目标反查，行动结果继续修正认识。本轮新要求优先；旧方案的具体实现不自动成为硬性要求。

# 用户已定的输入与学习起点

原型初始具备基本的三维空间理解能力。它应持续建立并修正对世界的三维理解，保留位置、外观和空间关系方面的线索。

初始允许的动作以 Minecraft 提供给玩家的动作接口为参照。前进、后退、跳跃、转视角等操作的效果不能预先写入，需要通过教师带领执行动作、自行观察变化来学习。教师只带着执行，不额外提供动作含义、因果解释、答案或对错评价。原型能够区分并记住自己刚才尝试了哪个动作。

用户已定：第一版允许原型在工作台交互与背包交互中自由尝试物品合成，通过观察操作结果积累经验。带说明的成熟物品合成功能留到后续考虑，具体阶段尚未指定。

Codex 对该分期的范围解释：第一版重点是开放尝试并能够从结果学习，暂不以掌握完整合成体系作为验收条件。沿用此前学习边界，现成配方与物品用途不直接作为原型已有知识写入；物品在世界中、手上和界面中不同外观之间的联系，可通过拾取、取用等经历来学习。后续是否需要利用界面文字说明或其他说明来源，另行明确。

原生身体感受以 Minecraft 提供的角色自身状态为参照。内部需要，以及状态改善、恶化的基本感受可以原生具备；食物是什么、怎样满足需要、哪些行为造成哪些后果，都要通过学习认识。好奇与耐心也纳入内部状态和自主活动的调节。

“合法交互”仅指接口与环境允许执行的操作。不能预置针对未知事物的保护知识或保护规则。第一版不做声音输入，也不依赖外部语言目标。

用户已定的环境功能：原型会随活动逐渐饥饿，进食能够缓解，同时不发生死亡；死亡与重生暂不纳入第一版行为验收。用户希望采用和平环境，具体设置待后续落实。用户目前尚未安装 Minecraft，已明确暂缓环境安装与配置，继续功能讨论。

Codex 待后续核实：游戏安装后，检查所选版本及环境设置能否同时满足饥饿消耗、进食恢复与不死亡。和平难度仍允许某些环境伤害，难度也会影响饥饿与生命恢复机制，不能仅凭模式名称认为上述条件已实现。[Minecraft 官方生命值说明](https://www.minecraft.net/en-us/article/health-minecraft)、[Minecraft 官方游戏模式说明](https://www.minecraft.net/en-us/article/what-minecraft)。环境测试条件与原型是否预装危险知识分别处理，后者仍遵守此前要求。

# 用户已定的对象与情景能力

原型先观察位置和外观，再通过合法交互认识性质。尚未知道一片区域是不是独立物体时，也可以先关注、观察和尝试，逐步认识它的边界。颜色、亮度、空间差异以及能否分离运动，可以成为倾向于将某些部分理解为独立物体的线索；这些判断可由后续经历修正。

原型能够理解整体及组成部分，分别关注和交互。组成关系变化后，能够理解整体的变化、分离部分的独立存在，并保留来源经历。例如树枝断开后，仍可认出原来的树，单独对待枝条，并记得它曾属于那棵树。

不确定时可以保留多种解释。例如两个相似对象遮挡后只出现一个，可以保留不同的身份可能，并利用后续线索区分。若后来发现认错对象，能够重新解释相关经历，修正归属及由此引出的判断；实际观察和尝试过的经历仍需保留。

回忆与内部预演期间，原型仍保持对现实的感知。相关的新变化可以打断原有预演，促使它更新当前情况并调整计划。

# 用户已定的预期与规则修正

相似场景可以唤起已有经验并产生预期，实际结果可以修正预期。更多结果相符的经历会加强预期。相似性不局限于外观，也涉及情景和相关条件。

预期落空时，原型能够主动寻找两次经历中不同的条件，并通过观察和尝试调查原因。找不到进一步原因时，削弱相关规则的置信度，保留这段未解释的经历。

规则随新经验逐渐演变，延续旧方案的设计思想。新的证据可以改变解释；长期记忆中的具体经历也能够在此基础上被重新理解。

# 用户已定的自主目标与规划

第一版以原型自主制定的目标为主。目标来源包括探索未知，以及饥饿等内部状态驱动。满足需要的方法由学习获得。 第一版也包括由经历逐渐形成、可随新经历改变的长期兴趣偏好，体现在更常选择某类探索活动上；不要求原型能够用语言解释“我喜欢什么”。具体偏好不预先指定，目标选择仍遵守已定的迫切性要求。

原型能够从已经学到的规律中形成多步中间目标，根据途中观察调整计划。内部预演属于第一版能力：在实际行动前，设想不同做法可能产生的后果，比较后再选择。关键信息不足时，可以把获取信息本身设为中间目标，通过观察和尝试补足，再继续规划。

正在执行目标时遇到与完成目标无直接冲突的疑问，先完成目标、记下疑问，空闲时再调查。更迫切的需要可以打断当前目标，转向优先级更高的目标，同时保留原有进度。

长期没有进展时，可以暂缓一个具体目标，记住尝试过什么、还缺什么信息；有新经验或条件变化后再尝试。暂缓时可以保留“目前还不知道怎样解决”的判断。

# 用户已定的耐心功能

- 在同一个目标上持续投入会消耗耐心。

- 与当前目标有关的进展可以补充或刷新耐心。

- 获得对目标有用的新认识也算进展，例如排除一个原先不确定的办法；重复得到已知结果不算新的进展。

- 在同一个目标的持续尝试中，每次刷新所补充的耐心逐渐递减。

- 达到切换阈值时，暂缓当前具体目标，重新选择。

- 重新选择仍服从需要的迫切性。例如仍然很饿、却一直拿不到某份食物时，应寻找其他食物来源。

耐心搁置后如何恢复，见下文的 Codex 补充假设；当前没有确定具体数值或计算规则。

# 用户已定的长期记忆

原型需要长期保留一些重要的具体经历，即使其中的通用规律已经学会。例如仍能记得在哪里发现过食物、对具体对象做过什么、结果怎样，以及对象的来源、未解疑问和被中断的目标。 用户确认的联合验收场景：原型离开曾发现食物的地点后，饥饿可以唤起相关记忆；在已经探索过的区域内，依据记住的地点和沿途线索主动返回，再观察核实食物是否仍在，并根据当前情况继续行动。该场景归入已有长期记忆、空间理解与目标规划的协作要求。

相似状态会唤起相关记忆；当前目标会影响主动注意、回忆和尝试的内容。经历发生时的状态，也会对记忆的牢固程度和持续时间留下影响。例如饥饿时发现食物可能留下更深的记忆，之后即使已经吃饱，这种差别仍可存在。

旧方案中“经历用于巩固后删除”的做法，不能作为所有长期记忆的统一要求。保留、整理与遗忘的具体边界仍需在后续设计中明确。

# 两侧联动的功能草案

以下是 Codex 依据已定功能整理的协作含义，供继续核对。它不决定模块数量、存储位置或连接结构。

| 方向 | 需要表达的信息 |
| --- | --- |
| 状态侧提供给概念侧 | 当前观察、相关的具体对象和关系、自身状态、尝试过的动作、随后结果、相关经历、当前目标、尚未解决的信息缺口，以及哪些内容仍不确定。 |
| 概念侧提供给状态与行动侧 | 对当前情景的解释与补全、后果预期、适用条件和可信程度、需要核实的线索、候选动作及中间目标。 |

概念网络继续承担概念与规律学习、补全、预测、缺失条件反查和目标规划。状态侧需要使具体情景、经历和当前活动可供这些能力使用。长期记忆、内部预演和目标管理的最终归属与协作方式留给整体设计。

# 继承边界与 Codex 补充假设

**既有项目边界**：外界信息以画面观察为基础；具体状态应有依据地可读。不可见变化不能全知，应区分当前观察、上次观察、估计和未知。真实经历、预测、目标与预演需要保持区别。旧代码作为参考，理论设计完成后再从零重建。

**Codex 补充假设与验收边界**：

- 暂缓后耐心可以逐步恢复，同时保留此前投入的历史。刚切换目标再切回来，不应仅靠切换就获得无穷耐心；具体恢复规律待验证。

- 提出一个未经核实的可能原因，不等于已经解释预测落空，不能借此永久维持旧规则置信度。

- 反复预演不能被当成多次真实验证。记忆深刻或容易被唤起，也不自动等于相关规则拥有更多外界证据。

- 自身状态接口提供身体感受；外界对象的性质、身份和规律仍需观察与学习。可用接口内容由 Codex 核实。

- 第一版扩展验证可以限制测试情景的复杂度，但不能把“未来需要什么、因此该做什么”的答案直接写入原型。

- 各种能力的运行时间、资源限制、记忆取舍、状态可读性和失败后的处理，需要纳入后续题目及验收；这些具体限制尚未确定。

这些补充不冒充用户已经逐项批准的要求。

三月方案主要是围绕语言模型构建认知扩展层；视觉在当时属于扩展输入。旧 `State` 专指主观需求与内稳态，范围与本轮的具体情景及经历不同。项目记忆明确记载：当时因纯文本输入难以提供可靠的身体依据，独立 `State` 后来被移出第一版；该文件保留为历史探索。当前 Minecraft 方案有动作和自身状态反馈，可以重新评估原来的取舍，但还需要验证感知、学习和反馈是否真正接通。

## 与本轮已定方向相互印证的部分

- 自身状态会影响注意、记忆唤起、目标选择和持续投入。既有讨论已覆盖其中多项，研究材料进一步提醒我们检查它们是否在同一次行为中共同发挥作用。

- 当前被打断的活动、未解疑问和长期经历需要延续；有新证据时能够重新理解。原型没有外部任务时也能自主活动。

- 真实观察、内部猜测和预演应保留来源区别。系统能记住“自己曾这样想过”，但这一经历不能独自证明外界确实如此。

- 重要经历应影响后续行为，而非仅存在于一个可检索的档案里。

- 主动回顾与系统性巩固仍按本轮决定放在第二阶段；第一版的自主行动、按需回忆和目标延续继续保留。

## 对概念网络联动的启示

以下是 Codex 对功能关联的解释。第一版要求以本轮已定功能和分期为准，额外的旧方案候选不作为进入设计阶段的前提。

1. 第一版继续从具体经历学习当前条件、动作与结果之间的关系，并用实际结果修正预期。对自身能力和熟练度的系统性认识保留为后续候选，不作为第一版动作学习或目标规划的前提。

2. 第一版已确定包括经验形成的长期兴趣偏好。同一种外界情形在不同需要与经历下可以具有不同的行动吸引力。对“我愿不愿意做”的影响，应与“外界规律有多少证据支持”分别判断。

3. 熟悉经验带来的快速补全和行动，仍需要接受当前观察核对。重新观察发现不匹配时，能够修正具体情况、预期和计划。

4. 原型对当前注意、目标、尝试及不确定性的可读说明，应依据实际运行情况。将来接入语言表达时，这些信息应已有可供表达的依据。

这些要求规定双向信息的含义与期望行为，具体表示方式、连接结构和模块归属仍留给后续整体设计。

## 需要保留为参考而重新审视的旧安排

- 旧稿中的固定三元组、字段表、流程节点、硬指定模块连接与策略模板，属于历史实现方案。当前仍以仿真动态网络为基础；若最终必须采用类似安排，应按用户要求逐项说明设计对象、方案、必要性及对通用性的影响。

- 旧注意力报告中的离线评分、规则基线与训练标签，属于另一种训练安排。若从中借鉴方法，须检查是否预先提供了任务答案、动作含义或教师对错评价；当前教师带领学习仍只提供动作执行经历。

- 旧稿的权限与保护门主要服务于电脑、工具和网络操作；不能据此给 Minecraft 原型预装针对未知危险的保护知识。

- 情绪、熟悉感与记忆深刻程度会影响处理倾向；它们怎样影响学习速度仍需设计，但不能仅因反复回忆或强烈感受而制造新的外界证据。

- 长期偏好、习惯和短时变化的尺度应允许不同。一次失败是否足以改变某项认识，取决于证据及适用条件，不沿用“一次事件永不形成稳定认识”之类统一规则。

- 原方案关于意识、真随机和情绪轴的论述，保留为其理论假设与设计动机。当前提取可观察的功能与可反证的行为要求，不据此认定意识或生物机制已经得到验证。

- 多个模块共同受到同一记忆或未解问题影响时，要检查同一份经历是否被重复算成多份证据。旧注意力重构中关于重复表示与重复影响的教训，可以转化为本轮整体一致性验收。

## 后续数学与仿真出题素材

以下只补充题目素材，尚不预先固定方程或作为用户批准的新能力：

- **经验与知识组**：第一版检验具体情景中的动作结果学习与预期修正；重复回忆同一经历不算新增真实样本。区分对环境的认识与对自身能力的系统性认识，保留为后续候选题目。

- **自主目标与行动组**：比较熟悉路线、未尝试路线与发生条件变化的旧路线，观察是否兼顾经验利用、核对与探索。

- **耐心与记忆组**：设置短暂新奇、重复无关刺激及真正相关变化，检验注意能否返回、目标是否合理延续。

- **耐心与记忆组**：第一版检验不同互动历史能否形成可追溯、可修正的兴趣偏好，并检查更迫切需要能否合理改变选择。记忆容量、细节衰减和概要保留的具体办法，由后续设计提出并验证。

- **整体协作组**：教师停止带领、外部语言模块不可用时，检查系统是否仍能根据当前情况、已有经历和内部需要继续活动。该项检验现有自主功能，不要求提前实现第二阶段主动回顾。
