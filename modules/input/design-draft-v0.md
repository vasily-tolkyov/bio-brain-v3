# 输入模块设计草案 v0

【候选方案】本稿是输入侧设计提案；字段与时序详见 [接口契约](interface-contract.md)，拍板编号 Q1–Q8 作为后续对齐索引。

## 1. 假设

### 已确认前提

- 【用户已确认】状态侧路径为：保留位置的稀疏输入 → S-SPACE 分布式活动峰 → 相互作用形成整体。
- 【用户已确认】范围是视觉优先的图像入网、身体信号和自身动作经历进入、其他接口适配；不预装 Minecraft 对象编号、世界地图、隐藏属性或配方。
- 【用户已确认】原生基本三维能力仍是要求；深度不确定时三维活动如何表达不确定尚无拍板。
- 【用户已确认】状态网络管 S-SPACE，概念网络管吸引子学习，动作模块管 L-GOAL／L-BODY／L-ACTION-TRACE；本稿只写输入侧交接面，跨模块变更须先对齐。

### 候选假设与材料边界

- 【候选方案】以稳定的传感器位置拓扑作为视觉路由依据；事件中的索引指测量位置，不指对象、概念或神经元身份。
- 【候选方案】视觉、身体测量、传出副本采用不同事件类型，共用可追溯的时间与来源信息；来源分离不要求三套独立物理网络。

## 2. 视觉通路：保留位置稀疏化 → 进入网络

【候选方案】流程为：图像采样 → 声明栅格／裁剪／缩放变换 → 稀疏选择 → 发出位置与强度 → S-SPACE ingest。裁剪或降采样后仍能把每个事件追溯到原图位置；拓扑不可换成按强度排序后的名次。

### 稀疏算子候选与展示依据

【展示工具已实现但未验证机制】local_contrast_topk 对 3×9 示意块中每个位置 p，以同列三值 a、b、d 作正局部对比：max(0, (3×raw[p]−a−b−d)/3)；在全部 27 个位置中选正值最大的 K 个，等值按位置索引排序，再除以峰值。无正值时输出全零。展示常用 K=6，这不是已确认参数，也不是逐列选 K 个。

【展示工具已实现但未验证机制】beat_sparse_map 保留非零位置的原索引，并按索引激活对应展示神经元。该映射能播放不等于其空间邻接、噪声鲁棒性、三维能力或识别机制已验证。

【候选方案】Q1 对照分块局部对比 topK、局部阈值和阈值加预算三种选择；任何方案均在原坐标域选点，输出位置索引和强度。测量通道可按亮度或传感器分量区分，但不预分配「树／门／工具」等语义特征通道。

【开放/未决】分块边界可能造成邻接断裂，全局 topK 可能挤掉局部弱信号，峰值归一化可能把低对比噪声放大并丢失绝对幅度；本稿把这些列为实验问题，不宣称已有解法。

### 与 S-SPACE 的交接面

- 【候选方案】VisionSparseEvent 至少携带位置索引、强度、帧号／采样时间、拓扑版本引用；可选传感器不确定度与深度证据。强度不直接解释成概率。
- 【候选方案】TopologyDescriptor 声明栅格大小、行列到索引的映射、邻接约定、坐标轴与原图变换；相邻位置的输入路由应保持可核验的邻接关系，不能随机打散或按对象分类后重排。
- 【候选方案】S-SPACE ingest 接收位置保持的活动注入请求；输入侧不给目标神经元清单、核宽、抑制项、峰数或稳定规则。注入后的分布式峰和整体相互作用由状态模块设计。
- 【开放/未决】只传原位置与拓扑，还是输入侧生成低层三维支持域，待 Q2、Q3 对齐；「按位置入网」不等于把二维像素直接声明为确定的世界三维点。

## 3. 身体信号与自身动作经历如何进入

【候选方案】身体适配器读取主体可测的内部量或本体感觉，声明变量来源、单位、量程和采样方式，发 BodySignalEvent 至 L-BODY 接收面。零读数、缺测、无效、过期分开；不能从外部事件或隐藏世界表推造身体当前值。

【候选方案】借鉴 M12 的变量声明隔离思路，保留原始连续值作为对照；分箱或低层变化量可作为 Q5 的编码选择。设定点、驱力、目标生成、学习规则及身体状态持有均留给动作／相关接收模块，不由输入适配器生成。

【候选方案】传出副本来源于动作侧真实下发记录：动作模块提供低层执行端口、参数、下发时刻及关联号，输入侧封装 ActionEfferenceEvent 交 L-ACTION-TRACE。后续执行确认／失败／取消只按实际反馈追加，不把「下发」当作「已成功」；视觉或身体后果仍由各自传感通道独立报告。

【候选方案】参考历史叙事 §11.1，观察与动作经历保持类型和来源分离；动作记录与后果可用时间及关联号对照，但关联号不是因果结论，不直接触发学习规则。预演和目标意图不进入真实经历入口，学习隔离机制由接收方负责实现并核验。

【候选方案】动作模块拥有 L-BODY／L-ACTION-TRACE 的逻辑表示及存储，输入侧只持适配配置和短暂传输缓冲；两端不各维护一份权威身体／动作历史。若 L-BODY 同时是读数源与接收职责名，用独立来源路径去重，避免回环。

【开放/未决】接收方、确认节点、物理存储位置、身体量的具体可测清单与缓冲寿命尚需对齐；历史「输出层镜像」不作为本稿新增的输出层承诺。

## 4. 其他接口适配原则

- 【用户已确认】其他接口也不得预装 Minecraft 对象编号、世界地图、隐藏属性或配方。
- 【候选方案】适配器外置，只交主体可获得的原始可测信号或低层传感器形，例如接触读数、接口原始字节；新增模态另立契约，不硬塞成视觉或身体事件。
- 【候选方案】每种适配器声明获取权限／来源、采样变换、单位、坐标、时钟与缺测方式；接口返回对象名、配方、全局坐标表等高层答案时，不能自动充当感官测量。
- 【候选方案】相机标定、栅格索引、身体传感器地址与执行器端口属于低层接线描述；不能借这些工程句柄传入对象本体、知识表或全局地图。
- 【开放/未决】尚未证明属于主体可测量的信息，应先列来源审查项，不默认进入网络；语言等高层指令如何接入另行对齐，不在本轮扩展为理解机制。

## 5. 三维／深度不确定的开放问题

【用户已确认】原生基本三维能力仍是要求，深度不确定时三维活动如何表达不确定是开放题。

【候选方案】深度信息注明来自实际测深、标定视差或显式声明的低层估计，并带坐标系、单位、估计方法与不确定度；没有证据时标未知，不补隐藏真值或默认深度。以下仅提出支持域的交接形状，不决定 S-SPACE 如何维持活动。

| Q3 选项 | 输入侧交付 | 接收面待对齐及代价 |
| --- | --- | --- |
| A | 【候选方案】像素视线方向＋深度区间，可附传感器可信度。 | 【开放/未决】S-SPACE 能否接收区间支持；单一区间如何保留中间不可能深度尚待讨论。 |
| B | 【候选方案】像素视线方向＋有限个深度假设及显式权重。 | 【开放/未决】权重是证据权重还是校准概率、假设数量上限及跨帧关联待定；不能用视觉亮度充当权重。 |
| C | 【候选方案】已标定视线＋深度未知标记；有合法测深时再附三维点及误差。 | 【开放/未决】接收方如何同时承载未定深度与三维点待定；该选项不是宣告仅凭二维输入已满足三维能力。 |

【开放/未决】Q3 拍板只确定输入证据形状；三维活动表示、坐标变换归属、遮挡后的持续、同物跨帧关联以及原生三维能力验收仍需状态侧联合设计。
