# 输入方案：两路观察怎样交给状态网络

【用户已确认】这轮先讲清方案，便于人读懂后拍板；只写文档，暂不改工作台。`mechanismValidated: false`：方向已经确认，不代表机制已被实验验证。

【用户已确认】可以把两台相机想成两只眼睛：各看各的，各交一张保留位置的稀疏表，再由状态网络里的活动相互作用，形成整体。这里不让输入模块先认出“这是一棵树”，也不给它游戏对象编号、地图、隐藏属性或配方。

【候选方案】“两路矩阵”就是两张仍有行列位置的数字表。一张来自左边相机，另一张来自右边相机。每张表只保留少数位置及其测量强度，传输时可以只列这些格子的地址和数值。两张表中相同的行列号，各指各的画面位置，不说明看见的是同一个东西；没有被选中的格子，也不等于那里没有东西。

【用户已确认】选点方向已经定为“分块局部对比 topK”：先把图像分成小块，在局部比较差异，每块优先留下较突出的少量位置。【候选方案】可理解为每块最多留 K 个正对比点，不够就少留。【开放/未决】块多大、K 取多少、怎样处理噪声和亮度变化还没定。【展示工具已实现但未验证机制】展示工具已有局部对比、topK 和按位置点亮，但动画能播不等于机制有效。

【用户已确认】选完位置，适配器才给每个位置加一条射线，单路观察可以不知道深度。【候选方案】射线像从眼睛朝某个方向伸出去的一条线：“信号来自这个方向，但多远还不知道。”记录时写清从哪里出发、朝哪里看、用什么参照系；不能随手在线上挑一点，说那就是物体的位置。两台相机出发点不同，也要保留这种差别。

【用户已确认】两路观察各交自己的矩阵和射线，分别送入状态网络；输入侧不先把点配对，再用三角测量算出世界坐标。三维交汇留给状态侧活动叠出。【候选方案】这样安排，是把“交出观察”与“形成空间状态”分清：输入先保留各路证据，不替状态网络提前作出哪个点对应哪个点的结论。【开放/未决】怎样避免错误交汇、怎样保留多个可能距离，还需要设计和实验。

【用户已确认】交接不是一对静止图片，而是两路随时间变化的稀疏矩阵。【候选方案】例如左边先来一帧，就更新左路；右边稍后到，再更新右路，各带自己的采样时间。下一帧左路没有选出任何点，只撤掉左路旧的输入驱动。右路断流则标成缺测，不能说成“右边看到全空”，旧观察也不能无限当作新观察；具体保留多久尚待拍板。

【用户已确认】输入侧负责保位置地稀疏测量、赋射线、分路交接；状态侧负责产生分布式活动峰，让活动相互作用，形成整体并承载三维交汇。【候选方案】可以把活动峰理解成网络里局部较活跃的一片。【开放/未决】它如何沿未知深度展开、如何处理移动和遮挡、没有新输入时能保持多久，都不能靠输入文档替状态侧定案，也不能把一个峰直接当作一个物体。

【开放/未决】这轮还需拍板五件事：一是每块留多少点、强度怎么算；二是射线起点、方向和标定从哪里来；三是未知距离怎样表达；四是各路更新时间、迟到和断流怎么办；五是接收端怎样兼容这些字段，以及拿什么实验判断交接正确、三维能力有效。【用户已确认】原生基本三维能力是要求；【开放/未决】是否达成仍须用证据回答。
