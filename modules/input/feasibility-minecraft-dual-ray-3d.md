## 一、结论摘要

【理论几何】**有条件能**：正确对应、共同可见且时序一致的点，在内参与带尺度的相对外参已知、三角化不退化时可恢复三维，因此“输入交射线、状态侧约束深度”的分工几何上自洽。

【理论几何】这里恢复的是有足够观测支持的三维点及可进一步约束的可见表面，不是仅凭任意两幅图恢复全部场景、遮挡背面、方块内部或对象身份；两组没有对应关系的像素位置，也不自动满足上述充分条件。

【开放/未决】【未验证网络机制】“S-SPACE 叠合景深”在本文中指通过多路空间约束收窄未知深度，不指光学景深或散焦测距；现有网络能否完成关联、排除错误交汇、形成稳定三维活动及整体，仍未验证。

## 二、像素为何能约束三维

### 2.1 内参把像素变成方向，外参把各路射线放进同一空间

【理论几何】设第 $i$ 路的像素齐次坐标为 $p_i=(u_i,v_i,1)^T$，内参为：

$$
K_i=\begin{bmatrix}
f_{x,i}&\gamma_i&c_{x,i}\\
0&f_{y,i}&c_{y,i}\\
0&0&1
\end{bmatrix}.
$$

【理论几何】其中焦距以像素为单位，$c_x,c_y$ 为主点，$\gamma$ 为轴间斜切项。以下假设已消除畸变，或使用无畸变针孔投影；有畸变时必须先恢复与针孔模型一致的像素方向。投影模型可对照 [OpenCV 官方相机标定说明](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)。

【理论几何】选定共同参照系 $F$，令 $C_i$ 为相机光心，$R_i$ 为“相机坐标 → $F$”的旋转，采用相机前方 $z>0$ 的约定，则：

$$
s_i p_i=K_iR_i^T(X-C_i),\qquad
q_i=K_i^{-1}p_i,\qquad
d_i=\frac{R_iq_i}{\|q_i\|},
$$

$$
\mathcal R_i=\{C_i+\lambda_i d_i:\lambda_i>0\}.
$$

【理论几何】这是本文从投影式直接得到的逆投影：一个像素约束一个方向，沿该方向的距离仍自由。因 $d_i$ 是单位向量，$\lambda_i$ 是光心到点的距离；它一般不同于光轴深度 $Z_i=[R_i^T(X-C_i)]_z$。不能混用“距离”“光轴深度”和图形管线的深度缓冲值。

【理论几何】只需双目之间的相对位置与朝向，就能取第一相机为局部原点进行三角化；不需要预先知道世界地图或绝对世界坐标。基线长度决定恢复结果的尺度，绝对世界位姿只决定怎样把局部结果放进世界参照系。

### 2.2 两条正确对应的射线决定深度

【理论几何】若两像素来自同一空间位置 $X$（同步观察同一点，或两次观察之间该点静止），且该点在两相机前方，则有：

$$
C_1+\lambda_1d_1=C_2+\lambda_2d_2,
\qquad
\underbrace{\begin{bmatrix}d_1&-d_2\end{bmatrix}}_{A}
\begin{bmatrix}\lambda_1\\\lambda_2\end{bmatrix}
=\underbrace{C_2-C_1}_{b}.
$$

【理论几何】无噪声、两射线不共线、方程一致且两距离为正时，交点唯一。若 $A$ 满列秩，可写 $\hat\lambda=(A^TA)^{-1}A^Tb$，再代回求点；满秩本身不保证射线相交，还必须检查残差与正深度。

【理论几何】静态场景可以使用异步两帧，只要分别采用各自采样时刻的实际相机位姿；同步双目也可以测量运动点在该时刻的位置。不同时间的未知运动点则不满足上述共同 $X$ 条件。

【理论几何】有像素量化、标定误差或定位误差时，两条空间直线通常异面，不应要求精确相交。可以求正向射线上的最近点对作为几何诊断，也可以在明确误差模型后最小化重投影误差；最近点对的中点不自动等于像素噪声模型下的最优估计。此区别见 [Hartley 与 Sturm 的三角化原始论文](https://perception.inrialpes.fr/Publications/1997/HS97/HartleySturm-cviu97.pdf)。

【候选方案】若将来制作几何对照，应同时报告重投影残差、射线夹角、正深度和不确定度，保留不一致或多解结果；这里的求解式只用于说明可观测性，不把三角化添加到输入模块，也不指定 S-SPACE 必须运行此算法。

### 2.3 视差公式、尺度与退化

【理论几何】在已校正的水平双目特例中，取同朝向光轴、相等水平焦距 $f$、相机中心 $(0,0,0)$ 与 $(B,0,0)$，其中 $B>0$。定义消除主点偏移后的视差，则由两次透视投影直接得到：

$$
\Delta_u=(u_L-c_{x,L})-(u_R-c_{x,R})=\frac{fB}{Z},
\qquad Z=\frac{fB}{\Delta_u}.
$$

【理论几何】该简式不直接适用于任意旋转、不同焦距或未经校正的双目；一般情况用各自的 $K_i,C_i,R_i$。只知道基线方向而不知道长度时，$B$ 与 $Z$ 同比例缩放不会改变像素，故无法得到绝对尺度。

【理论几何】设两单位方向夹角为 $\theta$，则 $\det(A^TA)=1-(d_1^Td_2)^2=\sin^2\theta$。以下情况需要区分：

| 条件 | 几何后果 |
| --- | --- |
| 【理论几何】基线为零，或同光心仅旋转。 | 对应射线转换到同一参照系后重合，不能新增深度约束；同一张图裁成两路也不产生双目基线。 |
| 【理论几何】射线平行、反向平行或近乎共线。 | 精确情况下可能无有限交点或存在连续多解；近退化情况下深度对误差极敏感。点落在相机基线方向附近也可能退化。 |
| 【理论几何】基线很短，或目标相对基线很远。 | 视差和交会角小，数学上可有唯一解，但数值精度可能不足以使用。 |
| 【理论几何】相机光轴平行，但看向同一个有限远点。 | 不等于观测射线平行；常规平行双目正是可用配置。 |
| 【理论几何】基线增大。 | 在共同可见且正确匹配时可改善深度敏感度，但不保证整体更好，视野重叠、遮挡及外观变化可能变差。 |

【理论几何】忽略焦距与基线误差，仅对视差误差作一阶传播，有 $\sigma_Z\approx Z^2\sigma_{\Delta_u}/(fB)$。例如 $f=800$ 像素、$B=0.5$ 长度单位、$\sigma_{\Delta_u}=0.5$ 像素时，$Z=10$ 的视差为 40 像素、深度标准差约 0.125；$Z=50$ 的视差为 8 像素、深度标准差约 3.125。该例是公式演算，不是 Minecraft 实测或网络性能。

### 2.4 “两路像素”不等于“已知对应点”

【理论几何】配对必须指向同一物理表面点，不能仅凭像素行列相同、亮度相近或都是方块角点。极线约束能排除一部分不可能的配对，但不能在任意场景中唯一决定对应；遮挡轮廓在不同视角中甚至可能对应不同表面点。极线几何的条件可对照 [Hartley 与 Zisserman 的原始教材章节](https://www.robots.ox.ac.uk/~vgg/hzbook/hzbook2/HZepipolar.pdf)。

【理论几何】一个只用位置的反例：令 $f=800$、$B=1$、两路水平主点均为 640，所有点位于同一极线 $v=c_y$；左图只见横坐标集合 $\{640,720\}$，右图只见 $\{480,560\}$，不提供可区分身份的外观或表面先验。两种一一对应分别给出：

| 对应方式 | 恢复的三维点，单位与基线一致 |
| --- | --- |
| 【理论几何】$640\leftrightarrow480$，$720\leftrightarrow560$。 | $(0,0,5)$，$(0.5,0,5)$。 |
| 【理论几何】$640\leftrightarrow560$，$720\leftrightarrow480$。 | $(0,0,10)$，$(1/3,0,10/3)$。 |

【理论几何】这两组不同的点集都在两相机前方，精确重投影到同样的两组像素；因此仅有未配对的位置集合，即使标定准确，也不普遍保证唯一三维。把所有射线一起叠加，会同时支持真实交汇与可能的错误交汇；出现峰并不能自行证明对应正确。

【开放/未决】当前分块局部对比 topK 还可能在两路中选中不同物理点；稀疏表里的单个对比强度不是跨视角身份描述。仅靠现有载荷、几何和时序能在什么场景下消歧，须单独检验，不能默认为已经具备特征描述子、稠密对应或对象识别。

## 三、Minecraft 特例怎样落到这些条件上

### 3.1 FOV、分辨率与内参

【理论几何】在中心对称的透视视锥、方形像素、零斜切、无裁剪和后处理变形的条件下，令实际渲染视口为 $W\times H$，竖直视场角为 $\theta_y$，宽高比为 $a=W/H$，则：

$$
f_y=\frac{H}{2\tan(\theta_y/2)},\qquad
f_x=f_y,\qquad
\theta_x=2\arctan\!\left(a\tan(\theta_y/2)\right).
$$

【理论几何】若给定的是水平视场角，则用 $f_x=W/[2\tan(\theta_x/2)]$。这由视锥边界的正切关系推得；竖直 FOV 与视口宽高比的参数含义可对照 [微软官方透视投影说明](https://learn.microsoft.com/en-us/windows/win32/opengl/gluperspective)。不能把水平和竖直 FOV 按宽高比直接线性相乘。

【理论几何】像素中心约定也必须一致：若像素中心取 $(j+0.5,k+0.5)$，对称视口主点为 $(W/2,H/2)$；若中心以整数 $(j,k)$ 编号，主点相应为 $((W-1)/2,(H-1)/2)$。裁剪、缩放改变像素到光线的关系；若图像变换为已知二维齐次矩阵 $T_{\rm img}$，则 $K'=T_{\rm img}K$，或先把像素还原到原图再求射线。

【开放/未决】Minecraft 的版本、相机模式、模组和采集路径尚未锁定，不能直接将菜单 FOV 当成本帧 $\theta_y$，也不能将窗口尺寸、界面缩放尺寸或视频输出尺寸冒充实际渲染视口。目标端须核实 FOV 轴向、单位、当前有效值、主点和裁剪缩放；例如 Bedrock 官方命令允许设置并渐变 FOV，说明只记录一次静态菜单值不足以覆盖所有相机设置。[官方相机命令](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/commandsreference/examples/commands/camera?view=minecraft-bedrock-stable)

【候选方案】可优先从获准的相机标定或实际渲染投影参数建立逐帧有效的 `geometry_ref`；非对称视锥、投影抖动等情形应按实际投影矩阵和视口逆投影，不能硬套中心对称 FOV 简式。具体读取通道未实现，也未在本轮批准。

### 3.2 通常无镜头畸变，不等于任意游戏画面都满足针孔模型

【理论几何】对题设的标准透视游戏相机，投影是数学视锥，通常没有真实镜头的径向、切向畸变，可以采用零镜头畸变模型；这是一项针对渲染路径的模型假设。透视缩短本身属于针孔投影，并不是必须校正的镜头畸变。

【开放/未决】目标截图是否经过非线性屏幕扭曲、镜头效果、动态分辨率、抗锯齿时间混合或自定义着色器，仍需核验。若像素已不对应单一时刻、单一光心的一条直线，必须恢复其成像关系或显式标为不适用；“游戏相机”四个字不能替代这项检查。

### 3.3 外参从何而来，玩家位姿还缺什么

【理论几何】固定虚拟双目只需两光心之间的相对旋转与带尺度平移；单相机在两个位置拍摄也可提供两条射线，但须知道两次实际相机位姿，并要求场景点静止或已有独立的运动补偿。两路来源的名称、帧号或“玩家向右移动”这样的动作命令均不构成外参。

| 来源 | 在本问题中的位置与限制 |
| --- | --- |
| 【候选方案】已标定的双相机安装关系，或受控渲染的虚拟双目配置。 | 可在相机组局部参照系给出基线与朝向，无须对象坐标或世界地图；要核对采样时刻及单位。 |
| 【候选方案】获准提供的相机位姿或实际渲染视图矩阵。 | 可建立跨路、跨时刻变换；若由玩家位姿派生，还须纳入玩家到相机的变换及渲染时刻。 |
| 【候选方案】从多帧视觉与允许的身体测量估计自运动。 | 属于额外的估计问题，需要关联、足够运动及误差控制；只有视觉时通常还缺尺度。不能把“可估计”写成当前已经提供准确外参。 |

【理论几何】由变换复合可得，已知完整玩家位姿并已知玩家到相机的变换时，$T_{F\leftarrow C}(t)=T_{F\leftarrow P}(t)T_{P\leftarrow C}(t)$。仅玩家位置不足以决定相机姿态；仅视向也不足以决定完整姿态，除非滚转或上方向另有约定。眼高、第三人称偏移、相机摇晃和渲染插值都可能使后一变换随时刻变化。

【候选方案】Minecraft 的可获取性有官方接口依据：Bedrock 相机系统支持独立自由相机及位置、旋转配置，实体接口提供 `getHeadLocation()` 与 `getViewDirection()`。这些分别描述相机控制或实体状态，不等于已经取得与每张图严格对齐的实际渲染相机位姿；这一步是本文据接口语义作出的限制性判断。[官方相机系统](https://learn.microsoft.com/en-us/minecraft/creator/documents/camerasystem/cameracommandintroduction?view=minecraft-bedrock-stable)、[官方实体接口](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/entity?view=minecraft-bedrock-stable)

【开放/未决】本题允许讨论“已知／可获取玩家位姿”的条件分支，但[现行输入草案](design-draft-v1.md)和[接口契约](interface-contract.md)仍要求几何来源合法，不读隐藏世界位姿。故本稿证明的是“若该位姿被允许且确实提供，几何可以成立”，并不把游戏接口可读取等同于本方案已授权接入。实际来源归 P2；深度缓冲、方块命中查询和地图真值也不能冒充像素推导的深度。

【开放/未决】现行 `ray.origin` 草案使用米，Minecraft 实验可能使用方块单位；须明确长度单位及转换，不能把无尺度的平移方向或未声明的方块坐标写成米制光心。恢复相机组局部结构不要求获得绝对世界原点。

### 3.4 方块离散网格与连续交点并不冲突

【理论几何】即便场景只含完整单位方块，在网格对齐坐标中，某个方块面可写为 $x=k$，但面内的 $y,z$ 仍连续。像素射线命中的是表面某处，不必是整数格点、顶点或方块中心；把三角化结果逐坐标取整会改变测量含义，也可能将表面点移入方块内部。

【理论几何】已知方块边长、轴向和网格偏移时，可以把“表面符合网格”作为额外几何约束；连续三角化与后续网格解释是两个步骤。相机组局部参照系不天然与网格对齐，周期网格也不自动消除错配或揭示遮挡后的占据；若靠已知方块尺寸恢复尺度，就明确使用了额外尺度先验。

【候选方案】可将网格只用于后续候选表面的约束或评估，并保留测量误差，不在输入侧把射线吸附成确定格点。

【开放/未决】是否允许该网格先验、如何估计其方向与偏移、怎样处理半砖、台阶、实体及自定义几何，尚未决定；本次不能借“Minecraft 由方块组成”默认获得完整场景模型。

## 四、缺少内参、外参或对应时，分别缺什么

【理论几何】下表将“有没有空间约束”和“能否恢复带尺度三维”分开；涉及多点估计时，均额外要求足够的正确对应、适当场景与非退化观测。

| 已有信息 | 缺失或仍有的歧义 | 能说到哪一步 |
| --- | --- | --- |
| 【理论几何】单路像素位置与内参。 | 每个点的沿射线距离；若需外部坐标，还缺相机到该坐标系的变换。 | 能得到相机局部方向，不能从该点的一次观察独立确定深度。 |
| 【理论几何】两路正确对应、内参、带尺度相对外参。 | 仍须排除退化、遮挡及运动不一致。 | 满足条件时可恢复共同可见点的带尺度三维，不需要绝对世界位姿。 |
| 【理论几何】两路内参与外参，但只有未配对位置集合。 | 跨路关联，可能存在多个同样合法的点集。 | 有几何约束；没有对任意场景的唯一恢复保证。 |
| 【理论几何】像素与内参，但无相对外参。 | 两套相机坐标系的相对旋转、平移及尺度。 | 不能直接把局部射线叠在一起；足够对应下可估计本质矩阵与相对位姿，但通常只得平移方向、缺绝对尺度。 |
| 【理论几何】像素与相对外参，但无内参或等价投影标定。 | 焦距、主点、成像轴向等像素到视向的映射。 | 已知基线也不能直接给每个像素赋正确射线；例如平行双目只知 $B$，仍有 $Z=fB/\Delta_u$ 中的焦距—深度歧义。特殊额外约束可能支持联合标定，但不普遍保证。 |
| 【理论几何】仅两路像素，内参与外参均无，但提供足够正确对应。 | 相机与结构共同的射影歧义。 | 一般非退化情况下可得到射影重建；长度、角度、平行关系等欧氏度量并未因此确定。 |
| 【理论几何】仅两组像素位置，连对应也没有。 | 关联歧义叠加相机、结构与尺度歧义。 | 不能普遍保证唯一三维；几何匹配在部分场景有帮助，但不能补成无条件充分性。 |

【理论几何】本质矩阵恢复的平移仅确定到尺度，见 [OpenCV 官方 `recoverPose` 说明](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)；未标定两视图的射影重建边界见 [牛津视觉几何组的原始教程](https://www.robots.ox.ac.uk/~az/tutorials/cvpr03_part1.pdf)。增加已知尺寸、自标定约束、足够多的合适视角或允许的身体测量，可以改变可恢复范围，但须显式列为额外信息。

【理论几何】纯旋转、缺少视差及某些平面或临界配置会让未知相机的估计退化或多解；这不表示“已知相机时任何平面都不能三角化”。一个普通可见平面上的正确对应点，在非退化已知双目中仍可恢复。

## 五、单图透视先验与双射线测量的差别

| 途径 | 深度依据 | 结论边界 |
| --- | --- | --- |
| 【理论几何】单图与针孔模型。 | 透视规定像素与方向之间的关系。 | 点沿同一射线移动不会改变该点的投影，故有透视不等于已知距离。 |
| 【理论几何】单图加消失点、已知尺寸、已知平面或方块网格等先验。 | 用额外结构限制射线上的候选位置。 | 在相应条件下可推断姿态、平面或部分尺度；错误先验会造成错误深度，也不保证任意场景唯一恢复。 |
| 【候选方案】学习型单图深度。 | 从训练数据与模型中引入统计先验。 | 属于独立能力与数据来源；本方案未说明已具备此模型，不能拿其可能输出补足当前几何论证。 |
| 【理论几何】具有已知相对位姿的双射线。 | 同一物理点必须同时满足两个投影约束。 | 在正确对应、非退化条件下产生可检查的深度测量；有尺度基线才有相应尺度的结果。 |

【开放/未决】状态网络也许会利用时序、邻域或概念先验辅助关联，但具体证据、接口和机制尚未确定。不能把“神经网络可能学会深度”作为当前稀疏射线方案已能消歧的证明。

## 六、与当前输入方案对齐

### 6.1 已确认的分工与输入应交付的证据

【用户已确认】依据[输入设计草案 v1](design-draft-v1.md)第二至四节及[通俗方案](scheme-plain-zh.md)：输入侧先做保位置的分块局部对比 topK，再为保留点赋射线；两路或多路矩阵各随时间演化、分别 ingest；输入侧不先进行跨路配对、三角测量或输出确定世界点，三维交汇由状态侧活动承载。

【候选方案】沿用[现行接口草案](interface-contract.md)的字段讨论交付，不在本文件另立已实现接口：

| 输入证据 | 几何上为什么需要 |
| --- | --- |
| 【候选方案】`source_id`、`view_id`、`frame_id`、采样时刻与时钟。 | 保留视角和观测时间；不同路相同索引或帧号不代表对应或同步。 |
| 【候选方案】`position_index`、`intensity`、`topology_ref`、图像裁剪缩放与编码说明。 | 保留位置及低层测量来源；强度既不是对象身份，也不是深度概率。 |
| 【候选方案】逐点 `ray.origin`、单位 `ray.direction`、`coordinate_frame`、`depth.status=unknown`。 | 表达“从哪里朝哪个方向看到证据”，保留双目基线，不预选一个深度。 |
| 【候选方案】`geometry_ref`、内参／投影关系、相对变换、单位、标定版本及有效时刻。 | 使射线可解释、可追溯；只给相机局部坐标而缺跨路变换时，明确尚不能共同定位。 |
| 【候选方案】可用的像素、角度、位姿与时间误差信息。 | 使状态侧能区分细射线近似与有厚度的可行区域；缺失误差信息不等于零误差，超出现行字段的表达仍待协商。 |
| 【候选方案】逐路完整性、空帧／缺测语义与有效期。 | 新证据、过期驱动和内部持续活动有不同含义；稀疏表中未列位置不能解释为自由空间。 |

【理论几何】输入不负责配对，不会破坏像素到射线的几何正确性；它只是把关联未知量保留给后续系统。若上游稀疏化没有留下跨视图共同点或可用于消歧的信息，下游不能仅凭模块分工凭空补出被丢失的测量。

### 6.2 “叠合”成立到哪一层

【理论几何】将一条射线理解为一个点的几何可行集合：已知对应的两集合相交，可把沿线未知距离收窄到一点；考虑误差后，交叠的是有限精度的区域。这说明“先交方向约束、后形成三维约束”没有几何矛盾，不要求输入先输出点云。

【开放/未决】【未验证网络机制】从上述集合关系到“分布式活动自然形成正确深度峰”，仍缺活动载体、映射、误差传播、来源区分、关联规则、竞争或其他消歧过程及收敛证据。不能把集合交运算等同于已存在的网络动力学，也不能将同一路多个点的支持误计为独立双目支持。

【开放/未决】当前[状态侧设计](../state-network/S-SPACE-01-sparse-feature-to-spatial-peak.md)仍明确将二维到三维留待专题，其接口表还列有旧 `samples[].depth_evidence`；[状态侧接口备注](../state-network/interface-notes.md)也未形成与输入 v1 的 `view_id`、逐点 `ray`、`geometry_ref` 完整一致的接纳契约。这是待对齐项，不是本稿已经完成的接口更新。

### 6.3 必须保留给状态侧或联合设计的未决项

| 未决问题 | 责任与不能提前假定的内容 |
| --- | --- |
| 【开放/未决】关联与错误交汇。 | 状态侧须说明如何利用合法证据处理重复纹理、同一极线多解和同类多实例；不能要求输入偷偷先配对，也不能默认任意交汇即正确对象。 |
| 【开放/未决】沿射线的深度不确定表达，对应 P3。 | 使用射线支持域、深度分布还是多假设活动，厚度如何随角误差与距离变化，均待状态侧设计；有限计算范围不等于观测到的近远边界。 |
| 【开放/未决】共同参照、尺度与自运动，对应 P2。 | 输入侧声明合法标定、单位和采样变换；未知的跨时位姿与尺度由状态侧／身体接口联合研究，不能默认为已知。 |
| 【开放/未决】跨路时序、迟到与驱动寿命，对应 P4。 | 分别 ingest 是交付方式，不是允许混合任意时刻；状态侧须确定时间兼容性及动态场景的处理。 |
| 【开放/未决】可见性、遮挡和历史持续。 | 单路可见时保留沿线未知或已有状态的相应不确定性；不能把缺测当不存在，不能从未知深度射线直接断言沿途为空。 |
| 【开放/未决】从几何支持到活动峰、归组与整体。 | 空间载体、邻接、动力学、稳定性、峰分离与读出均待验证；正确三维点本身也不自动提供对象边界或实例身份。 |
| 【开放/未决】稀疏信息是否足够及联合验收，对应 P1／P5。 | 测量共同点保留率、错配、三维误差、覆盖率和歧义保留情况；阈值、输入参数与必要扩展应先约定，不能用动画或单一漂亮例子替代。 |

## 七、风险清单

| 风险 | 影响与边界 |
| --- | --- |
| 【理论几何】内外参误差。 | FOV 轴向、主点、像素中心、裁剪缩放、相机眼高或朝向错误，会把方向与起点系统性放错；小重投影残差也不保证尺度标定正确。 |
| 【理论几何】小基线、远距离及极线退化。 | 深度误差迅速放大；无视差时不能强行给出有限确定深度。 |
| 【理论几何】同步误差与场景运动。 | 两路不同时间看到移动点时，通常不存在应共同相交的同一个 $X$；知道相机运动并不等于知道物体运动。 |
| 【理论几何】遮挡、低纹理与重复方块纹理。 | 可能没有共同可见点，或出现多种合法配对；稀疏 topK 还会降低共同点覆盖，强度归一也可能削弱外观区分信息。 |
| 【理论几何】非朗伯外观、透明及反射。 | 视角变化可能移动高光或混合多个表面，使亮点不再对应同一物理点；单个表面几何仍可透视投影，但常用外观匹配假设可能失效。 |
| 【开放/未决】特殊着色器、折射或递归传送门视图。 | 若画面显示的是另一空间的虚拟相机或分段光路，原相机的一条普通直射线模型不够；此项针对相关模组／效果，不假定普通 Minecraft 传送门一定显示远端世界。 |
| 【开放/未决】HUD、手持物、粒子、天空与画面后处理。 | 可能采用屏幕空间、不同投影或不适合静态表面点的模型；需明确有效输入范围。实体／区块未被渲染也不能直接解释为空世界。 |
| 【开放/未决】【未验证网络机制】叠合后的伪峰、峰合并与错误持续。 | 即使各条射线计算正确，状态更新仍可能选择错误交汇、混淆来源或延续过期证据；必须独立验证。 |

【候选方案】首轮可控几何样例可限定为固定投影、已知非零基线、静止不透明场景、关闭非线性画面效果，并记录实际采样相机参数；这些是隔离问题的实验条件，不是所有 Minecraft 场景天然满足的性质。

## 八、理论论证与机制验证的交付边界

【理论几何】本文给出了针孔逆投影、正确对应下的双射线解、尺度及退化条件，并用两种合法配对产生不同点集的反例说明“未配对位置集合”不普遍唯一。它支持的是条件性的几何可行性。

【候选方案】后续验证可分两层，二者都需要明确失败结果：

1. 【候选方案】几何对照：由评估端保有投影真值及正确对应，检查像素到射线和三角化误差，并覆盖零基线、远点、错配和时间错位；正确对应只供几何对照，不塞进真实输入接口。
2. 【候选方案】状态机制：只向待测系统交付约定的逐路稀疏矩阵和射线，检查共同点不足、多解、遮挡、重复纹理及运动条件下，是否形成有证据支持的三维活动并保留歧义；评分端真值与输入隔离。

【开放/未决】【未验证网络机制】本轮只完成文档论证与数值例子的算术、重投影核对，没有连接 Minecraft、实现上述实验或验证 S-SPACE 动力学；也未将任何候选标成已确认。`mechanismValidated: false` 保持不变。
