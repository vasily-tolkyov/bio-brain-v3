【用户已确认】`mechanismValidated: false`。本轮只形成可评审的输入方案文档，保留 v0；不修改 `data/architecture.json`、其他模块，不执行 git commit／push；工作台和状态网络留待另轮同步。

## 当前方向

- 【用户已确认】路径：保留位置的稀疏输入 → S-SPACE 分布式活动峰 → 相互作用形成整体。
- 【用户已确认】Q1-A 已选定分块局部对比 topK；【开放/未决】K、块大小、对比细节和强度尺度仍待拍板。
- 【用户已确认】适配器先稀疏测量，再赋视线／射线；输入侧不钉死世界三维点。单视角交方向射线，深度可以未知。
- 【用户已确认】多视角各自产生随时间演化的独立稀疏矩阵和独立射线，分别 ingest；输入侧不先匹配点对、不先三角测量，三维交汇由状态侧活动叠出。
- 【用户已确认】要求原生基本三维能力；禁止 Minecraft 对象 ID、地图、隐藏属性和配方；【开放/未决】深度不确定表达及能力验收仍待定。

## 阅读顺序

1. 【候选方案】先读 [通俗方案](scheme-plain-zh.md)：用人话解释两路矩阵、射线、时间与职责。
2. 【候选方案】再读 [设计草案 v1](design-draft-v1.md)：具体流程、相对 v0 的变化、五个拍板点和验证提案。
3. 【候选方案】最后读 [接口契约](interface-contract.md)：多路身份、逐样本 `ray`、分别 ingest、空帧／缺测和兼容语义；字段和 API 均为提案。
4. 【历史草案·可能冲突】[设计草案 v0](design-draft-v0.md) 原样保留；其 Q1 仍待选、可先以标定视差生成深度、射线可选等表述不再作为当前方向。v0 中指向接口契约的链接现指向演进后的 v1，不构成旧接口快照。
