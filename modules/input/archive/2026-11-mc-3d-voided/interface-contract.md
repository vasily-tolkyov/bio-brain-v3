# 输入侧接口契约 v2 候选：MC 单路整帧

【用户已确认】MC 首版采用单路 2D 视角＋可锁定相机参数 K；先稀疏再赋射线。相机没有测深，`ray.depth` 保持未测，禁止把推算／预测深度写回观测或 `ray.depth`。

【候选方案】本稿给出单路优先的交付形状：一个 `VisionSparseEvent` 表达一帧保留位置的稀疏亮点，携带强度、时间、来源、拓扑、几何引用和逐样本 ray。整帧全部亮点一次交出，不逐 ray 渐进发布；逻辑接收面暂记 `ingest(event, topology, geometry)`。

【开放/未决】`mechanismValidated: false`。字段名沿用可用旧名，具体 schema 版本、配置、函数名和接收实现尚未联合签认；文档版本 v2 不表示已有可部署 API。拍板点见 [设计 v2](design-draft-v2-mc-monocular.md)。

【历史草案·可能冲突】[v1 契约全文](archive/2026-11-dual-view/interface-contract.md) 已完整归档。旧“双路分别 ingest、由状态交汇叠出三维”不再是当前 MC 默认入口；`view_id` 见第 8 节的历史兼容／未来扩展边界。

## 1. 单路来源、时间与帧

| 字段 | 候选约束与含义 |
| --- | --- |
| `schema_version`、`adapter_version` | 【候选方案】必填非空版本标识；新版具体取值待双方分配，不直接复用旧 v1 曾提议的载荷版本 2。不支持的版本报错。 |
| `session_id`、`source_id` | 【候选方案】会话与真实相机流标识；当前只提交一条相机流，流键候选为二者组合，不需要左右视角键。 |
| `source_path`、`provenance` | 【候选方案】必填的采集通道、低层变换及版本来源；标识不能夹带对象身份、隐藏位置或答案。预测和重放不借此冒充本帧真实采样。 |
| `event_id`、`frame_id`、`sequence` | 【候选方案】分别标识交付事件、原采样帧及同流非负整数序号；它们只关联采样，不赋对象或跨帧实例身份。重复／冲突处理见第 5 节。 |
| `sampled_at`、`clock_id` | 【候选方案】必填有限非负采样时刻与时钟标识；评审起点用会话内单调毫秒，时钟换算须显式，不拿到达顺序代替采样时间。 |
| `received_at` | 【候选方案】由接收端记录的到达时刻，发送端可省略；必须说明接收时钟，不冒充采样时刻。 |
| `time_uncertainty_ms` | 【候选方案】可选有限非负时间误差；未声明不能解释成零误差。 |
| `capture_ref` | 【候选方案】新增待对齐引用，绑定原图、本帧身份／时间与锁定采集配置；可在独立 capture 记录中放图像摘要与配置摘要，不携带世界真值。具体结构未定。 |
| `topology_ref`、`geometry_ref` | 【候选方案】必填，引用同一帧适用的不可变拓扑／几何版本；几何描述显式含 K 或能解析到锁定 K，不允许按需猜参。 |
| `update_mode`、`frame_complete` | 【候选方案】首版候选固定为 `snapshot`、`true`，表示全部保留亮点已到齐；不支持增量或半帧注入。 |
| `validity` | 【候选方案】视觉观测入口候选只接受 `valid` 的完整采样。缺测、无效或过期不能作为带空 samples 的合法观测；是否另设采集通知字段待定。该字段仅描述采集可用性，不为自然场或相对布局分桶。 |
| `valid_until` | 【候选方案】若用于在线输入驱动，显式截止时间使用采样时钟且晚于 sampled_at；不得缺省成永久有效。若采用另行协商的寿命规则，须给出规则引用。【开放/未决】离线单帧与在线接纳的统一表示、期限和到期动作未定。 |

【候选方案】公共来源与时间名称也可用于身体／动作事件；视觉专用的帧、拓扑、K、ray 字段不自动成为非视觉必填项。

## 2. 保留位置的亮点集合与逐样本 ray

| 字段 | 候选约束与含义 |
| --- | --- |
| `samples` | 【候选方案】必填列表，表达整帧全部保留亮点；可为空。未列位置没有提供测量，不表示自由空间或对象不存在，不补成伪零观测。 |
| `samples[].position_index` | 【候选方案】原栅格内唯一整数，范围为 0 到 H×W−1；候选行优先 `index=v×W+u`。不能用强度排名、对象号或神经元号替代。 |
| `samples[].intensity` | 【候选方案】有限正数，范围和量纲由强度编码明确；候选可归一到 (0,1]，须保留所用尺度，不自动解释成概率、深度或可信度。 |
| `samples[].measurement_uncertainty` | 【候选方案】可选，说明测量误差类型、值与单位；无声明不等于无误差，未知值不填零。 |
| `samples[].ray` | 【候选方案】每个保留亮点必填，含下表字段；赋值发生在稀疏选择之后。 |
| `intensity_encoding`、`scale_metadata` | 【候选方案】必填的可解析编码说明，含分块、局部对比、每块 k、边界／并列规则和幅度尺度；K 仅表示相机内参。A 如何从强度取得沉积预算须另有显式映射，不默认系数为 1。 |

| ray 字段 | 含义与边界 |
| --- | --- |
| `coordinate_frame` | 【候选方案】必填非空参照名，与 geometry 一致；优先评审 `camera:<frame_id>` 形式的本帧相机局部参照，无合法外参时不声称世界位置。 |
| `origin` | 【候选方案】必填三维有限数组，长度单位由 geometry 明示。本帧相机局部参照的光心为 [0,0,0]，这是坐标定义，不是把未知世界位姿填零。 |
| `direction` | 【候选方案】必填三维有限单位向量，朝场景前方；按像素及 K 生成，须与 geometry 一致。非法值或非单位向量报错，接收端不静默修正。 |
| `depth` | 【用户已确认】本轮保持 `{"status":"unknown"}`，表示相机未测深，禁止写回推算／预测深度。【候选方案】该对象不附 value、距离、终点、区间或假设列表，也不另设并行 depth_evidence。 |
| `angular_uncertainty` | 【候选方案】可选方向误差说明，须有类型和单位；结构、容差与接收支持范围待联合确认，不能补零或静默忽略不支持的声明。 |

【候选方案】射线只给出 `origin + λ×direction，λ>0` 的方向支持，λ 未测；有限 RF 计算域是状态侧承载配置，不能填成 ray 的近远测量界限。

## 3. 拓扑、锁定 K 与帧绑定

| 描述 | 字段与候选约束 |
| --- | --- |
| `TopologyDescriptor` | 【候选方案】保留 `topology_id/version/shape/index_layout/adjacency/coordinate_frame/axes/image_transform/calibration_ref`；明确高宽、行列索引、像素中心、原图映射及邻接，跨块不改变位置含义。 |
| `GeometryDescriptor` | 【候选方案】保留 `geometry_id/version/calibration_ref/coordinate_frame/axes/length_unit/valid_time_range/provenance`；补充锁定 K、图像尺寸、投影／畸变模型、像素中心与变换说明、采集锁定记录引用。两份描述中重叠项必须一致。 |
| 锁定 K 的内容 | 【候选方案】明确 3×3 内参矩阵及 fx、fy、cx、cy 的像素含义；fx、fy 为有限正值，矩阵可逆。首个候选为零斜切、无畸变针孔，不从分辨率或菜单 FOV 自动猜主点与焦距。 |
| 锁定采集记录 | 【候选方案】记录真实采集版本、投影／FOV 定义、画面尺寸、变换及参数来源，经独立投影核对后锁定；每帧必须绑定适用版本，不用当帧拟合值替代。 |
| `capture_ref` 的绑定 | 【候选方案】可解析到本帧原图摘要、frame_id、采样时刻、锁定记录摘要及采集版本，并与事件核对；摘要只能核查绑定，不能单独认证相机真实性。 |
| 图像与射线参照 | 【候选方案】图像用 u 右／v 下，本帧相机用 x 右／y 下／z 前；像素中心由配置明示。图像坐标不冒充三维坐标，同名 calibration_ref 须一致。 |
| 长度单位 | 【候选方案】origin 等长度值明示单位；如需方块与模型米转换，给出明确比例与来源，不能默认一块等于一米。局部原点为零也不能省略单位。 |

【候选方案】首个候选输入限定为未裁剪／未缩放的上述针孔画面，按 `direction=normalize(K⁻¹[u,v,1]ᵀ)` 赋 ray。这里归一化是声明的生成步骤；接收端校验失败不能修值。若需其他投影或变换，先对齐描述及支持范围，不能临时套公式继续成功。

【用户已确认】几何／K 真错配硬失败。【候选方案】缺必需几何字段、锁定配置与实际帧不符、像素／ray 不一致、绑定错帧或不支持的变换都使整帧失败；即使一起改 K、FOV 和摘要令它们内部自洽，也不能替换独立锁定配置。

【开放/未决】实际 MC 的投影获取、锁定认证、数值容差、像素中心、HUD／覆盖与误差模型尚未联合落实；状态侧合成配置和示例参数不能自动成为真实相机配置。

## 4. 整帧接纳与错误

1. 【候选方案】先验证版本、来源／时刻、完整性、拓扑／几何／帧绑定，再验证全部位置索引、强度、ray 与字段支持。任何一项不合法就整帧报错；不丢坏点、不补值、不发布部分贡献。
2. 【候选方案】全部通过后，一次交出并接纳整帧 `samples`，由状态侧按固定 A 规则在固定 RF 上沉积自然场。内部循环计算不构成逐 ray 接口；输入不规定核宽、场的计算域或活动读出算法。
3. 【候选方案】普通新帧一次替换该单路外部输入驱动，不把两帧拼成当前观测；拓扑与几何版本在帧边界一起生效。具体在线替换、寿命与内部活动持续仍待签认。
4. 【候选方案】完整合法采样的 `samples=[]` 可表达本帧未选中亮点；缺图、损坏或不完整采样直接报告采集错误，不能伪造空帧。缺测通知若采用独立入口，也不能刷新旧帧时间或当作空帧清除。
5. 【候选方案】成功返回只表示本次整帧已接纳，可引用 event_id／frame_id；错误返回明确字段或绑定原因。这里的成功／异常是调用结果，不是场、物体或布局的分类，也不表示机制验证通过。

【候选方案】几何未知距离是合法观测边界；几何真错配是错误。两者不能合并成“无法测距就拒收”，也不能用没有测深掩盖已经发现的 K 或 ray 错配。

## 5. 时间、重复与持有范围

【候选方案】单路事件保留原采样时刻，序号递增；评审起点为迟到／到达时已过期则报错，不通过改时间戳接纳。在线驱动按显式期限结束，缺测不延寿；离线复算不成为真实观测的再次注入。

【开放/未决】`sequence` 的范围、同采样时刻处理、`event_id/frame_id` 复用、重复与迟到容限、`valid_until`／寿命规则、容量和返回字段尚需联合拍板。[状态侧 06](../state-network/S-SPACE-06-mc-monocular-state.md) 已指出重复幂等与冲突硬失败的旧口径差异。

【候选方案】对已识别的重复采样或身份冲突先以报错、不重注入、不延寿作为评审起点；不沿用旧稿“同内容幂等成功”的默认语义。本稿不新增持久去重、对象、占据或历史账本，不承诺已能检测任意历史重复；如何在单路当前接纳信息内满足时序约束仍须设计。

【候选方案】输入只需处理当前完整帧、适配配置和必要的临时交付缓冲；状态侧负责 A 的活动。观测引用供同一采样的只读核对，不被解释为跨帧对象身份或另建权威历史。

## 6. 单路示例

【候选方案】以下仅为几何和整帧交接摘录，省略版本、来源说明、capture、时序期限及完整描述对象，**不是可直接提交的完整请求**。示意栅格 H=4、W=4，整数像素中心，行优先；K=[[2,0,2],[0,2,2],[0,0,1]]，无裁剪／缩放。相机局部 x 右／y 下／z 前，length_unit=block；这些合成数值不是 MC 默认值。

```json
{
  "source_id": "mc-camera",
  "frame_id": "f10",
  "sampled_at": 1000,
  "clock_id": "session-monotonic-ms",
  "topology_ref": "grid-demo-4x4-v1",
  "geometry_ref": "camera-demo-k2-f10",
  "update_mode": "snapshot",
  "frame_complete": true,
  "validity": "valid",
  "samples": [
    {
      "position_index": 10,
      "intensity": 0.8,
      "ray": {
        "origin": [0, 0, 0],
        "direction": [0, 0, 1],
        "coordinate_frame": "camera:f10",
        "depth": {"status": "unknown"}
      }
    },
    {
      "position_index": 11,
      "intensity": 0.4,
      "ray": {
        "origin": [0, 0, 0],
        "direction": [0.4472135954999579, 0, 0.8944271909999159],
        "coordinate_frame": "camera:f10",
        "depth": {"status": "unknown"}
      }
    }
  ]
}
```

【候选方案】索引 10、11 对应像素 (2,2)、(3,2)，经同一 K 得到上列单位方向。两点在一次整帧调用中交出，不拆成两次 ray 发布；没有第二视角、配对键或深度终点。示例只核对几何一致性，不提供真实 MC 接入证据。

| 边界例 | 候选行为 |
| --- | --- |
| 完整下一帧未选中亮点 | 【候选方案】用该帧真实时间、完整引用与空 samples 一次交出，不添加零强度样本。 |
| 图像丢失或像素未到齐 | 【候选方案】报错，不造一个完整空帧。 |
| 任一点 ray 与 K／像素不符 | 【候选方案】整帧失败，不提交其余“好点”，不改 ray 或 K。 |
| depth 中混入条件深度／预测值 | 【候选方案】拒绝该载荷，不静默删值后注入。 |
| A 外缺某段范围依据 | 【候选方案】该项条件坐标或关系不产生；原合法观测仍保持未测深度。 |
| A 外提交的依据真错配 | 【候选方案】包含该计算的请求硬失败，不能改成仅返回 A 的成功请求。 |

## 7. A 外计算的读取边界

【用户已确认】自然成像不贴真假标签；输入不交对象 ID、地图或配方；推算／预测深度禁止写回观测或 `ray.depth`。

【候选方案】对齐 [S-SPACE-07](../state-network/S-SPACE-07-relative-layout.md)：锁定 K 给出像素与方向关系；状态侧在 A 外另用适用的方块／等范围依据计算左右、近远与条件坐标。像素左右不等于三维 X 次序；前向 Z 不等于沿 ray 的距离 λ。缺依据就不产出对应项，不设置 resolved／inconsistent／partial 分桶。

【候选方案】范围依据、条件坐标和成熟模型预测不属于本视觉事件的观测字段；解释侧可只读原样本、K、A 与另行提供的适用依据，并保留本帧绑定。不能用对象 ID、隐藏深度缓冲、地图或默认 N=1 补依据，不能拿零或旧答案填缺失值。

【候选方案】A 的规则保持固定；成熟模块只能接在 A 外作解释／先验，不能替代 S-SPACE 底座，不能回写 ray、强度、来源或采样时间，也不能把解释结果重新沉积为额外观测。辅助需要原始稠密图时，读取范围另行对齐，本契约不自动放行。

【历史草案·可能冲突】06c 较早的 B 返回 unknown／状态词不沿用为当前布局输出协议；这里唯一固定的 depth.status=unknown 只说明相机没测深。07 的条件计量结果不是新的观测深度。

## 8. 未来多路与旧稿兼容

【历史草案·可能冲突】旧 v1 要求 view_id、以多路分别 ingest 为主线，并用相机组基线讨论交汇；当前不把这些条件作为 MC 首版前提。完整旧字段与例子留在归档。

【候选方案】`view_id` 降为未来扩展／历史兼容元数据，不是当前必填字段，不编码对象身份或匹配关系。旧状态实验摘录若保留单路 view_id，是否接受及如何映射到当前 source_id 需显式协商；不能静默删字段后宣称已兼容。

【开放/未决】多路同步、共同参照、基线及多帧位姿另议；不得把新增视角或输入侧配对作为当前单路实现的隐含依赖。旧载荷缺 K、帧绑定或 ray 时不能自动标成新版，不用深度字段反造观测；迁移需有原采样资料与明确支持的版本。

## 9. 身体／动作候选简留

| 事件 | 保留字段与边界 |
| --- | --- |
| `BodySignalEvent` | 【候选方案】保留 body_schema_ref；measurements[].sensor_key/value/unit/validity/uncertainty；以及可选 encoding_ref、derived_samples。值来自真实身体测量，原始零值可有效，缺测不填伪数值；派生量保留来源与时间窗，不创建驱力或目标。 |
| `ActionEfferenceEvent` | 【候选方案】保留 action_instance_id、actuator_ref、command_payload、phase、feedback、feedback_at、observation_refs。只记录真实下发／反馈，下发不等于成功，关联号不表示因果；目标、预演和预测后果不能冒充执行经历。 |

【开放/未决】L-BODY／L-ACTION-TRACE 的接收归属、身体编码、动作阶段及写入确认点沿用待对齐状态。本轮不改字段语义或另建身体／动作账本，视觉 schema 演进不自动升级它们。
