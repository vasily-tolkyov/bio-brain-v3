# 输入侧接口契约草案 v1

【用户已确认】`mechanismValidated: false`。输入侧先保位置稀疏测量，再赋射线；多路矩阵分别 ingest，不先配对、三角测量或钉死世界点，三维交汇由状态侧活动叠出。

【候选方案】本稿是可评审的交付形状，不是已实现 API。相对旧契约，增加 `view_id`、`geometry_ref` 和逐样本 `ray`，把更新／撤销范围明确为单路；保留位置、强度、时间、来源、拓扑以及身体／动作候选字段。拍板点见 [v1 第五节](design-draft-v1.md#五仍开放的五个拍板点)。

【开放/未决】字段、版本号、时序和返回值尚未联合签认；[状态侧接口备注](../state-network/interface-notes.md) 尚未同步本轮演进，本轮不修改该模块或工作台。

## 1. 通道与公共信封

| 事件／方向 | 含义 |
| --- | --- |
| 视觉适配器 → S-SPACE ingest | 【候选方案】`VisionSparseEvent` 每次只带一路一帧稀疏矩阵及逐点射线，不携带跨路匹配或融合点云。 |
| 身体适配器 → L-BODY 接收面 | 【候选方案】`BodySignalEvent` 保留一批带单位的身体测量，不交驱力或目标；第 3 节沿用原候选字段。 |
| 动作侧下发／反馈 → 输入封装 → L-ACTION-TRACE | 【候选方案】`ActionEfferenceEvent` 保留一次下发或反馈，不把预演当真实执行；第 4 节沿用原候选字段。 |

| 公共字段 | 类型／约束 |
| --- | --- |
| `schema_version`、`adapter_version` | 【候选方案】非空版本标识；本轮视觉载荷提议 `schema_version=2`，文档版本 v1 与载荷版本分开。身体／动作不随视觉扩展自动升级，按各自事件类型协商版本。 |
| `session_id`、`event_id`、`sequence` | 【候选方案】前两者为非空字符串；会话内 `event_id` 唯一，序号为非负整数。视觉序号在 `(session_id, source_id, view_id)` 内单调；身体／动作仍按同源序号。事件键不表示对象身份。 |
| `source_id`、`source_path` | 【候选方案】低层传感器／执行端口标识与派生路径；相同读数的派生值保留共同来源，不能借标识传入对象本体。 |
| `sampled_at`、`clock_id` | 【候选方案】有限非负采样时间与时钟标识；动作则为实际下发或反馈时刻。首轮例子用会话内单调毫秒，跨时钟须有显式换算版本。 |
| `received_at` | 【候选方案】接收端记录的到达时刻，使用明确的接收时钟；发送时可省略，不冒充采样时间。 |
| `time_uncertainty_ms` | 【候选方案】可选有限非负时间误差；缺失表示未声明，不能解释成零误差。 |
| `validity` | 【候选方案】枚举 `valid`（有效）、`missing`（缺测）、`invalid`（无效）、`expired`（过期）；后三类不携带有效样本，不编码成有效零测量。 |
| `provenance` | 【候选方案】采样方式、真实测量来源及变换版本；只记录低层来源，不承载标签、世界地图或答案表。 |

【候选方案】真实经历入口只接受真实采样及真实下发／反馈；重放、预测、目标、预演须另行协商入口与来源标记，不通过改时间戳伪装成新经历。

## 2. 多路 VisionSparseEvent 与 ray

【用户已确认】多视角是两路或多路独立稀疏矩阵，各配自己的射线，分别交给状态网络；不是输入侧先输出一个融合后的三维矩阵。

| 视觉字段 | 类型／含义 |
| --- | --- |
| `view_id` | 【候选方案】必填非空视角标识，与 `source_id` 共同确定一路；更换路绑定须显式开新流或版本，不把左／右图串成同一路。 |
| `frame_id` | 【候选方案】本路内唯一帧标识；不同路帧号相同不表示同步或对应点，跨路不要求同帧号。 |
| `topology_ref`、`geometry_ref` | 【候选方案】分别引用不可变栅格描述与在采样时刻有效的几何描述；一个事件只使用一套版本。 |
| `samples` | 【候选方案】非零样本列表，压缩表达一张高×宽稀疏矩阵；未列位置为本次未选出的正驱动，不是无物体或自由空间证据。 |
| `samples[].position_index` | 【候选方案】声明栅格内唯一非负整数，指测量位置；不能用强度排名、跨路匹配号或神经元编号替代。 |
| `samples[].intensity` | 【候选方案】有限正数，首轮候选范围 `(0,1]`；强度不是概率、距离或深度可信度。 |
| `samples[].measurement_uncertainty` | 【候选方案】可选测量误差，附类型及单位；缺失不表示确定。 |
| `samples[].ray` | 【候选方案】每个有效样本必填，结构见下表；先稀疏测量再赋射线，不通过跨路匹配生成。 |
| `intensity_encoding`、`scale_metadata` | 【候选方案】记录分块、对比方式、K、边界、归一方式及幅度尺度；峰值归一时逐块记录尺度，不能把所有块共用一个不明峰值。参数均须显式声明。 |
| `update_mode`、`frame_complete` | 【候选方案】本轮评审起点为 `snapshot`（完整稀疏快照）和布尔完整性；有效视觉载荷须 `frame_complete=true` 才接纳更新。增量模式未获支持时显式拒收。 |
| `valid_until` | 【候选方案】输入驱动有效截止时间，与采样使用同一时钟且不得早于采样时刻；可由显式协商的逐路寿命规则替代，不能缺省为永不过期。具体期限待 P4。 |

| `samples[].ray` 字段 | 类型／含义 |
| --- | --- |
| `coordinate_frame` | 【候选方案】非空参照系标识，与 `geometry_ref` 一致；可为合法标定的相机组局部参照系，不要求世界参照系。 |
| `origin` | 【候选方案】长度为 3 的有限数值数组，表示该相机采样时刻在上述参照系中的起点，单位米；不同相机不强行共用原点。 |
| `direction` | 【候选方案】长度为 3 的有限数值数组，表示朝场景方向的单位向量；不得为零向量，单位长度误差容限须协商，不由接收端静默修正。 |
| `depth.status` | 【候选方案】首轮示例为 `unknown`（深度未知），此时不填距离、终点或世界三维点；几何含义为 `origin + λ × direction`，`λ ≥ 0` 且未知。 |
| `angular_uncertainty` | 【候选方案】可选方向误差，显式给出类型、数值、单位；缺失表示未提供。其结构和接收支持范围待 P2／P3。 |

【开放/未决】有合法测深时，是否扩展 `ray.depth` 为带来源和误差的区间／多假设类型，归 P3；v1 首轮仅以未知深度评审，不沿用旧 `samples[].depth_evidence` 的并行歧义字段。不支持的扩展必须拒收或按协商暂缓，不能丢弃后继续注入。

| 描述对象 | 字段与约束 |
| --- | --- |
| `TopologyDescriptor` | 【候选方案】保留 `topology_id`、`version`、`shape`（正整数高宽）、`index_layout`、`adjacency`、`coordinate_frame`、`axes`、`image_transform`、`calibration_ref`；候选行优先 `index=r×宽+c`，四／八邻接待选，裁剪缩放能回溯到原测量位置，跨块邻接不丢失。 |
| `GeometryDescriptor` | 【候选方案】新增 `geometry_id`、`version`、`calibration_ref`、`coordinate_frame`、`axes`、`length_unit`、`valid_time_range` 和 `provenance`，声明像素到方向的成像关系、相机相对起点／朝向及来源；若含动态变换，须绑定采样时间与变换版本。 |
| 两类坐标的关系 | 【候选方案】拓扑中的参照系描述图像位置，`ray` 的参照系描述三维方向；几何描述明确连接两者，同名 `calibration_ref` 必须一致，不能把像素行列当作世界米制坐标。 |

【候选方案】只知道相机自身坐标时，载荷明确标记该参照系；缺少跨路合法变换时，接收端报告不能共同定位，不自动当作同原点同朝向。缺失必需标定或方向时，本路返回不可解释几何的错误，不补默认射线；其他路仍可独立接纳。

【用户已确认】输入侧不先匹配跨路点、不三角测量、不提供确定世界点；【候选方案】视觉事件不设跨路点对表、对象 ID 或融合点云字段。传感器安装标定只描述低层几何，不能从隐藏世界位姿或地图偷取。

【展示工具已实现但未验证机制】v0 引用的列内对比、27 位置块内 topK、峰值归一及按索引点亮仅是展示依据；K=6 不作为本契约默认值，也不表示已实现多路射线交接。

## 3. BodySignalEvent

| 字段 | 类型／含义 |
| --- | --- |
| body_schema_ref | 【候选方案】身体变量声明版本：低层传感器键、单位、量程、来源与采样方式；不包含世界对象本体。 |
| measurements[].sensor_key、value、unit | 【候选方案】真实身体量／本体感觉的地址、有限数值及单位；超量程显式报告，不静默裁剪为合法值。 |
| measurements[].validity、uncertainty | 【候选方案】逐变量有效性及可选误差；缺测时不填伪数值，原始零值保持为有效零值。 |
| encoding_ref、derived_samples | 【候选方案】Q5 若采用分箱／变化量，附固定编码版本、原始测量引用及时间窗；不能抹掉共同来源或推导未来变化。 |

【候选方案】借鉴 [M12 身体修订](/workspace/bio-brain-runs/plans/m12-amendment-2026-10-20.md) 的适配原则，变量读数来自身体可测通道；具体分箱与变化量不是本模块已确认结构。设定点和驱力配置不进入测量载荷，不由输入侧创建目标。

## 4. ActionEfferenceEvent

| 字段 | 类型／含义 |
| --- | --- |
| action_instance_id | 【候选方案】动作侧签发的一次实际下发关联号；连接反馈与重复检测，不是对象／概念 ID。 |
| actuator_ref、command_payload | 【候选方案】低层执行端口及实际下发参数与单位，如关节目标或按键电平；不传隐藏动作后果、配方或语义动作知识表。 |
| phase | 【候选方案】下发、执行确认、结束、失败、取消等显式阶段；阶段来自实际记录，缺反馈时保持未知。Q4 决定哪些阶段写入经历。 |
| feedback、feedback_at | 【候选方案】可选真实执行反馈与时间；执行器确认不等于视觉／身体效果已发生。 |
| observation_refs | 【候选方案】可选已收到的感觉事件引用，仅表示可追踪关联；不填未经观察的成功结果，不据此判定因果。 |

【候选方案】动作意图、候选计划、目标、预演不可提交为此通道的真实执行阶段；下发记录由动作侧产生，输入侧不直接命令执行器，也不决定出手门与规划机制。

## 5. 时序与逐路接收假设

- 【候选方案】视觉流键为 `(session_id, source_id, view_id)`；各路各自递增序号、维护当前输入驱动和有效期。新会话不自动继承旧会话观察，几何／拓扑切换在单帧边界原子生效。
- 【候选方案】首轮按完整快照评审。同路新有效帧原子替换旧输入驱动；`valid`、`frame_complete=true`、`samples=[]` 是有效空帧，只清除此路驱动。空帧仍带本路描述引用和时间。
- 【候选方案】`missing`／`invalid`／`expired` 带空样本和 `frame_complete=false` 作为状态通知，不执行“空帧清除”；既有驱动按已协商截止时间到期撤销，状态内部活动是否持续另行决定。局部缺测不能伪装为完整有效快照，局部掩码另议。
- 【候选方案】同路采样时间不得倒退；同时间用序号区分。首轮评审选择迟到拒收并返回原因，重排窗口仍可在 P4 改选；跨路按实际采样时间及其误差解释，不用接收顺序认定同步或因果。
- 【候选方案】先校验版本、流身份、时刻、完整性、索引范围／唯一性、强度、射线有限值／单位方向、标定有效范围和字段支持，再按单路单帧原子接纳。若任一样本不合法，整帧拒收，不能注入半帧或覆盖旧帧。
- 【候选方案】重复 `(session_id,event_id)` 同内容幂等返回，不能重复注入或延长寿命；同键异内容拒收。不同事件号复用同一路 `frame_id` 时也须识别重复或冲突，防止同帧二次注入。
- 【开放/未决】更新方式、帧率、批量上限、排队方式、迟到和同步容限、输入驱动寿命尚未锁定；本稿不承诺实时性能。

## 6. 分别 ingest、例子与存储边界

【候选方案】逻辑接收面写作 `ingest(单路视觉事件, 拓扑描述, 几何描述)`，一次只更新一路；可共用同一函数及物理网络。调用名、传输协议和实现位置待对齐，不凭“分别 ingest”推出两套独立物理 S-SPACE。

【候选方案】每次返回本次 `event_id`、`source_id`、`view_id`、`frame_id`、结果和原因；结果可为接纳、重复、拒收、暂缓。接纳只代表契约检查和输入驱动更新，不表示成峰、匹配或三维机制成功；暂缓也不算已注入。

【候选方案】以下为正常样例的几何载荷摘录，整段仅用于评审，省略公共信封与描述对象，不能直接当完整请求。假设两台相机已合法标定到同一局部参照系，x 向右、y 向上、z 向前，两路各自栅格为 2×3；尺寸、基线、强度及时间均为示意值，不是默认参数。

```json
[
  {
    "source_id": "相机甲", "view_id": "甲视角", "frame_id": "甲10",
    "sampled_at": 1000, "clock_id": "会话时钟",
    "samples": [{"position_index": 1, "intensity": 0.8,
      "ray": {"coordinate_frame": "相机组局部参照系",
        "origin": [-0.03, 0, 0], "direction": [0, 0, 1],
        "depth": {"status": "unknown"}}}]
  },
  {
    "source_id": "相机乙", "view_id": "乙视角", "frame_id": "乙7",
    "sampled_at": 1004, "clock_id": "会话时钟",
    "samples": [{"position_index": 1, "intensity": 0.6,
      "ray": {"coordinate_frame": "相机组局部参照系",
        "origin": [0.03, 0, 0], "direction": [0, 0, 1],
        "depth": {"status": "unknown"}}}]
  }
]
```

【候选方案】上述数组只是并列展示两条独立记录：分别 `ingest(甲10, 甲拓扑, 甲几何)` 与 `ingest(乙7, 乙拓扑, 乙几何)`，不把数组作为一批融合输入。甲、乙矩阵的首行分别为 `[0,0.8,0]` 与 `[0,0.6,0]`，第二行全零；同索引不表示同一点，两条平行射线也不被强行求成交点。

| 后续边界样例 | 接收含义 |
| --- | --- |
| 【候选方案】甲11 有效完整，`samples=[]`，乙没有新帧。 | 【候选方案】只清除甲驱动，乙保留到其已协商有效期；不直接清零 S-SPACE 内部活动。 |
| 【候选方案】乙8 通知缺测，`frame_complete=false`，`samples=[]`。 | 【候选方案】标记乙缺测，不能当作“乙看见全零”；乙7 的驱动只按旧截止时间到期，不因通知延寿。 |
| 【候选方案】甲12 有有效样本但缺 `ray`／标定，或携带不支持的深度类型。 | 【候选方案】整帧拒收并说明原因，不覆盖甲的既有驱动，不影响乙接纳；暂缓分支须先按 P5 协商。 |
| 【候选方案】甲10 重复到达，或乙7 到达时已过截止时间。 | 【候选方案】前者幂等返回而不重新注入，后者拒收过期；不能改成当前采样时刻。 |

【用户已确认】输入交稀疏矩阵和射线；状态侧负责分布式活动峰及其相互作用、由多路活动叠出三维。输入不决定目标神经元、核宽、扩散、抑制、竞争、峰数、归组或概念学习规则。

| 对象 | 输入侧临时持有 | 接收侧责任与待对齐项 |
| --- | --- | --- |
| S-SPACE | 【候选方案】适配配置、单路事件与投递缓冲，不维护融合世界模型。 | 【候选方案】状态侧持有逐路驱动及内部活动，提供可核对来源／位置／射线的诊断；【开放/未决】具体存储与动力学另议。 |
| L-BODY | 【候选方案】真实身体测量及低层派生量，不覆写权威身体值。 | 【候选方案】沿用动作侧拥有身体表示与存储的交接提案；【开放/未决】接收责任和 Q5 编码未联合签认。 |
| L-ACTION-TRACE | 【候选方案】下发副本及实际反馈，只持投递状态，不补写成功后果。 | 【候选方案】沿用动作侧接纳并保存经历的提案；【开放/未决】Q4 写入阶段、存储寿命与接收口仍待定。 |

## 7. 禁止项与旧版兼容

- 【用户已确认】禁止 Minecraft 对象 ID、地图、隐藏属性、配方；输入侧不先配对／三角测量，不钉死世界点。
- 【候选方案】禁止把工程流键、事件号、几何元数据伪装成对象身份或隐藏世界真值；测试真值只由评分端持有。
- 【候选方案】禁止打乱位置、以排名覆盖索引、将强度当概率、缺测当零、未知深度当默认距离，或把两路来源丢弃后汇成同一矩阵。
- 【候选方案】禁止把目标／预测／预演写成真实经历，把动作下发写成成功，把关联号写成因果结论。
- 【历史草案·可能冲突】旧契约允许可选 `depth_evidence`，未要求每样本射线，也未明确逐路更新；不能把缺字段的旧载荷静默标成新版。
- 【候选方案】迁移旧视觉事件须有明确视角绑定和合法标定，重新按“先稀疏、后赋射线”生成新版事件并保留来源；不能凭旧深度字段反推世界点当新输入。缺少资料则拒收或协商暂缓，不默认补几何。
- 【开放/未决】P5 决定版本协商、不支持字段的拒收／暂缓分支与迁移验收；本稿未改变身体／动作载荷，不替接收方承诺兼容。
- 【展示工具已实现但未验证机制】展示可播放、按索引点亮、几何画线正确都不能证明输入或三维机制成立。
