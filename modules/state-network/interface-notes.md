# 状态网络接口备注

【用户已确认】`mechanismValidated: false`；动画成功不等于逻辑验证。

## 对外 ingest 假设

【用户已确认】输入采用 Q1-A 分块局部对比 topK，先稀疏再赋射线；各路独立矩阵及射线分别 ingest，不在输入侧先配对、三角测量或钉死世界点，三维交汇由状态侧活动叠出。观测口只收适配器真实稀疏测量与射线，补全／回映不进观测口。

【候选】本段按[输入 v1 契约](../input/interface-contract.md)第 1、2、5、6 节及 [S-SPACE-02 第五节](S-SPACE-02-multi-view-ray-3d-filter.md#五与-visionsparseevent-的字段对齐假设)同步接收侧讨论：逻辑接收面为 `ingest(单路 VisionSparseEvent, 拓扑描述, 几何描述)`。一次只更新一路，可共用函数与物理网络；逐路驱动寄存 → 沿射线注入共享活动载体 → 多路共支持下的模式筛选是逻辑分工，不是三套物理网络。

【候选】公共信封、`position_index`、`intensity`、`measurement_uncertainty`、`intensity_encoding`、`scale_metadata` 和 `topology_ref` 沿用输入命名，新增对齐 `view_id`、`geometry_ref`、逐样本 `ray` 及逐路有效期。输入 v1 提议视觉载荷 `schema_version=2`，仍待联合签认；S-SPACE-01 的旧 `depth_evidence` 不作为并行深度字段，缺射线的旧载荷不能静默升级。

【开放】这些仍是双方待确认的草案，不构成已实现 API 或机制承诺。深度扩展、时序阈值、寿命、增量与局部缺测掩码待对齐；本次同步不代表已在群内签认。S-SPACE-01 及本文件末尾原五点保留为前轮议题，当前三维专题的前五拍板点见 [S-SPACE-02 第七节](S-SPACE-02-multi-view-ray-3d-filter.md#七需用户拍板的前五点)，不重开 Q1-A 方向。输入侧对 L-BODY / L-ACTION-TRACE 的职责表述不自动升级为本轮确认。

| 交接职责 | 假设与边界 |
| --- | --- |
| 【候选】逐路身份 | 流键为 `(session_id, source_id, view_id)`；保留 `source_path`、`provenance`。不同路同索引或同帧号不表示对应或同步；同源派生、复制与重复事件不能新增独立支持。 |
| 【候选】输入侧提供 | 保位置的稀疏矩阵、逐点射线、来源、时间、拓扑与强度尺度；Q1-A 已确认，K、块大小与归一化参数仍由输入侧讨论。未列位置不表示自由空间。 |
| 【候选】几何与射线 | `geometry_ref` 绑定采样时刻有效的标定及变换版本；每个有效样本必填 `ray.coordinate_frame`、米制 `origin`、单位 `direction`、`depth.status=unknown`。保留各相机起点，未知深度不填终点或默认距离；误差缺失不表示零。 |
| 【候选】状态侧消费 | 整帧校验后原子替换本路寄存与外部驱动，几何／拓扑版本在帧边界一起切换；沿射线贡献保留可追溯来源并可逐路撤回。共享内部活动的持续与成峰规则仍待定。 |
| 【候选】观测语义 | 首轮以 `snapshot` 为起点；`valid` 且 `frame_complete=true` 才执行有效更新。完整空帧只撤销本路旧驱动；`missing/invalid/expired` 的空样本、不完整通知不作空帧清除，也不延寿；旧驱动按原截止时间撤销。 |
| 【候选】时序与寿命 | 保留 `sampled_at`、`received_at`、`clock_id`、时间误差和 `valid_until` 或协商逐路寿命；同路序号递增、采样时间不倒退。首轮以迟到／已过期拒收为起点，跨路共支持须另查时间兼容，不能按接收顺序或有效期重叠认定同步。 |
| 【候选】协议异常 | 先校验版本、流身份、时刻、完整性、全部索引、强度、射线有限值／单位方向和标定有效性；任一样本非法则整帧拒收，不覆盖旧驱动、不注入半帧、不影响其他路。缺必需射线或几何不补默认值。 |
| 【候选】幂等与结果 | 同 `(session_id,event_id)` 同内容幂等，不重复注入或延寿；同键异内容拒收，同一路复用 `frame_id` 也查重复／冲突。返回事件、来源、视角、帧、接纳／重复／拒收／暂缓及理由；接纳不表示三维成功，暂缓不算注入。 |
| 【候选】共同定位边界 | 仅有相机局部参照而缺跨路合法变换时，可保留可解释的逐路记录并报告不能共同定位，不假设同原点同朝向，不参与共同定位筛选。 |
| 【开放】深度与身体参照 | 沿线支持域／深度分布／多假设活动、计算域、误差传播与身体参照尚未选定；区间等深度扩展须先协商。不支持字段显式拒收或按约定暂缓，不静默丢弃后注入。 |
| 【开放/未决】身体与动作经历 | `BodySignalEvent`、`ActionEfferenceEvent` 可作为对接名称参考，是否经输入适配、如何连到 L-BODY / L-ACTION-TRACE、谁拥有存储仍待确认。 |

【候选】核验例：A10 与 B7 分别接纳；A11 完整空帧只撤 A，B 保留到自己的截止时间；B8 缺测通知不能延长 B7；A12 缺射线则整帧拒收，A 的旧驱动仅按原有效期处理。补全／回映和历史持续活动即便存在，也不能充当新增真实相机支持。合成／重放实验走隔离试验入口，不冒充当前真实观测。

## 对外读出假设

【候选方案】提供活动快照或可访问的活动引用，并附来源窗口、坐标域、位置映射版本和读出规则版本；这些工程引用不承担语义识别或实例身份。

【开放/未决】[工作台 1.1.0](../../data/architecture.json) 将 `P-SPACE-IN` 标作 `observation` 输入、`P-SPACE-OUT` 标作 `spatial` 输出，结构状态均为 `confirmed`；本轮只对照该记录，不扩张六项用户确认，不把端口定义等同于已实现活动读出。

【候选方案】可附峰摘要：支持域、极大区域、加权中心、峰宽、峰值、活动总量、背景衬比与证据引用。保留底层可测活动，使接收方能复算摘要，不把峰摘要当作唯一证据。

【开放/未决】峰摘要的模式、读取频率、是否推送、读写权限、查询关联句柄及缓存生命周期尚未确定；摘要不默认包含对象类别、持久实例 ID、确定三维位置或行动指令。

【候选方案】对无合格峰、未观测、载荷异常分别给出可区分的结果；不将这些结果合并为「环境中不存在」。

【开放/未决】L-GROUP、L-CALL、L-RETURN、L-HAVE、L-HAVE-QUERY、L-ACTION-TRACE、L-EXPERIENCE、L-BODY 是接线标识，其 P-* 端点及方向见 [README](README.md#与输入--概念--动作交接一览)，运行归属可讨论；不能仅凭名称推定网络数量或所有者。

【开放/未决】`L-GROUP` 为 `unresolved`；`L-SPACE`、`L-HAVE`、`P-INSTANCE-CALL` 与 `P-INSTANCE-RETURN` 为 `candidate`。输入契约称谓与结构接线之间的映射仍需联合确认，不能把所有 L-* 名称直接当作 S-SPACE 的函数端口。

## 禁止项与边界

- 【开放/未决】成峰机制尚未批准；禁止把「局部驱动+邻近支持抑制」或设计稿任一候选写成确定结构，禁止用图示连线替代机制批准。
- 【用户已确认】S-SPACE / S-INSTANCE / S-SOURCE / S-HAVE / S-WANT 仅是职责小框，不等于已批准五套独立物理网络。
- 【开放/未决】输入算子、概念吸引子学习公式与动作规划动力学仍由相应模块讨论；本轮禁止越权拍板其实现与参数。
- 【开放/未决】现实信号适配细节待定，但本轮接口禁止预装 Minecraft 对象编号、世界地图、隐藏属性或配方，也禁止用工程引用暗藏这些语义。
- 【仅工作台展示】展示中已有的稀疏化、亮斑或动画效果只能作为未验证的展示证据；禁止将其成功升级为机制验证，保持 `mechanismValidated: false`。
- 【历史参考·非本模块确认】newnet、light-line 和旧叙事中的锁定措辞只属于原材料语境；禁止据此升级本模块确认状态、移植学习公式或规划规则。

## 变更流程

【用户已确认】跨模块接口变更先在「原型设计」群对齐。

1. 【候选方案】提出变更时列出现有假设、拟变更字段 / 方向 / 时序、上下游影响和可核验样例；明确是否改变坐标、强度或观测语义。
2. 【候选方案】将输入、状态、概念、动作涉及的边界问题一并作为群内对齐材料；不以本稿发布或候选实验通过代替对齐。
3. 【候选方案】对齐后记录决定来源和适用版本，再更新相应接口文档；当前尚未对齐的项继续保留候选或开放标签。
4. 【候选方案】以已提供的 `architecture.json` 1.1.0 与 S-SPACE 摘录核对节点和接线，再补齐运行载荷与读写权限；结构差异回到同一对齐流程，不自动重写其他模块。
5. 【候选方案】接口兼容性与机制有效性分别记录，后者仍需可复算活动数据和实验依据；本轮仅交付设计文档，不执行群内通知。
